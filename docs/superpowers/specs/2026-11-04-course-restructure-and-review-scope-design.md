# 课程体系重排、讲评范围与呈现形式（Design）

- 状态：Approved（用户授权“后面的都你自己决定”，2026-11-04）
- 目标：让课程结构可按作者要求重排且可验证；讲评只围绕本次提交的题目；
  课程正文的呈现形式按需扩充（图表、代码块、提示块）
- 范围：
  - 内容：`content-packs/robot-quality-system/`（纯数据）
  - 作者流程：`.claude/skills/course-author/`
  - 引擎（两处小改动）：`src/testbridge/tutor/review.py`、
    `src/testbridge/contract/sanitize.py`、`src/testbridge/quality/lint.py`
  - 文档：`docs/course-briefs/robot-quality-system/`、`docs/ROADMAP.md`

---

## 1. 三个问题

### 1.1 课程结构无法按意图重排

现状：21 课由 3 个 `module.yaml` 的 `lessons` 列表决定顺序。概念之间有真实先修 DAG
（`concepts.yaml`），但课序不受它约束，也没有任何检查。作者想改叙事主线，只能手工
挪文件、改 manifest、改练习 ID，且没有任何机制告诉作者“这一版是不是真的更系统”。

具体症状：通用测试标准地图是第 15 课，而第 1 课就在用标准；安全标准、功能安全在
第 17–18 课，学习者读完全程才第一次接触“依据从哪来”。自动化/仿真验证（SIL/HIL）
在这门课里完全缺失，而它是机器人测试岗的核心技能。

### 1.2 讲评越界到未作答的题

`build_review_context` 调用 `build_context`（`tutor/context.py`），后者会把**整节课
所有练习的题干与选项**写进提示词。讲评第一题时，模型看到第二题的题干在上下文里、
而 `<submission>` 里没有它，于是输出“第二题还没做”。数据库里已有 2 条这样的
讲评（`exercise_review`），并会被永久缓存。

### 1.3 呈现形式单一

21 课里只有 2 张 SVG 图、1 课有 `<pre>` 代码块，其余全靠表格。净化器与 CSS 其实
已经支持 `figure/img/pre/code/details/aside/table`，缺的是作者侧的写法约定与内容。

---

## 2. 目标 / 非目标

**目标**

1. 新结构让每课在整体里有明确位置：模块即“幕”，课序与先修 DAG 一致，且该一致性
   由确定性规则强制（`lint.lesson_order`）。
2. 讲评上下文只包含本次提交的题目；旧版本缓存自动重新生成。
3. 课程正文按需使用图、代码块、提示块、对比表；每课至少一种“非纯文字”结构。
4. 重排流程写成作者 skill 的固定步骤，含 ID 迁移与数据影响说明。
5. 保留现有学习数据：有证据的课与练习 ID 不变，复习卡与掌握度不丢。

**非目标**

- 不从学员追问历史反推重排（会破坏“课程在框架外创作”的边界）。
- 不改判分、掌握度、调度、证据语义。
- 不引入全新的渲染器/图表 DSL；图仍是作者手写的本地 SVG +
  `<figure><img>`，代码块是 `pre[data-tb-block=code]`。
- 不做课程版本号自动化迁移；`pack.yaml` 版本手动升。

## 3. 方案：新课程结构

4 个模块，22 课，按“问题 → 依据 → 方法 → 缺陷 → 行业与认证”推进：

| 模块 | 主题 | 课 | 优先级 |

| M01 | 体系基线：策略、风险、标准、安全、分层、门禁 | 7 | P0 |
| M02 | 设计与验证：方法、任务链、预言、SIL/HIL、实验、Flakiness | 6 | P0 |
| M03 | 缺陷与度量：缺陷、根因、逃逸、覆盖、回归 | 5 | P0 |
| M04 | 行业与认证：汽车标准、性能、认证、综合 | 4 | P1 |

**为什么标准在第 3 课而不是第 1 课**：策略（#1）与风险（#2）是“问题”，标准（#3）是
“依据”。先有问题意识再给依据，比先背标准更接近真实岗位；同时把标准从第 15 课
提前到第 3 课，解决“前 14 课引用无基础”的问题。这也是唯一能让有学习数据的
两课保持原位、ID 不变的切分点。

**概念图**：21 个概念 ID 全部不变；新增 `sil-hil-validation`（prereq
`test-levels-shift`, `task-chain-fault-injection`），`quality-system-synthesis`
的 prereq 补上它。新序满足所有先修约束（逐课核对见 §7 验收）。

**练习 ID 规则**：`EX-<全局课序 3 位>-<序号>`。这是现有规则的延续（旧包同样是
全局序），保证全局唯一；MANIFEST 里的 `exercises` 与正文 `data-tb-exercise`
挂载点同步改名。

**数据影响**：`EX-001-01`、`EX-001-02`、`EX-002-01` 及其课 ID 不变 →
3 张复习卡、2 个概念的掌握度、逐条证据都继续有效，无需重建。
其余练习 ID 变化，但没有对应证据。

## 4. 方案：讲评范围收敛

`tutor/context.py::build_context(pack, lesson_id, *, exercise_ids=None)` 增加可选参数：

- `exercise_ids=None`（默认）：保持现状，列出本课全部练习题干（Tutor 追问需要）。
- `exercise_ids=[]`：不输出“练习”段。

`tutor/review.py::build_review_context` 改为 `exercise_ids=[]`：
被讲评的那道题已经在 `<submission>` 里出现（题干、选项、答案、解析、rubric），
其余练习的题干完全不进提示词。

`REVIEW_SYSTEM_PROMPT` 增加两条规则：

- 只讲评 `<submission>` 中的这一道题；不要提及其他练习、不要说“第 N 题还没做”。
- `strengths` / `gaps` 只能针对本次作答，不得要求补做其他题。

`PROMPT_VERSION` 升到 `review/2`；`ReviewService.review` 的缓存判断加
`stored.prompt_version == PROMPT_VERSION`，版本不符则重新生成并覆盖。这样
数据库里 2 条旧讲评会在下次访问时自动刷新，不需要手工清理。

## 5. 方案：呈现形式

不改契约与净化器语义，只加一个允许属性并约定写法：

1. **图**：`<figure><img src="../../../assets/figures/<name>.svg" alt="...">`
   `<figcaption>...</figcaption></figure>`。每课最多 2 张，按需；新增 SVG 遵循现有
   视觉语言（`#0f172a` 文字、圆角矩形、浅色填充、`role="img"` + `title`/`desc`）。
2. **代码块**：`<pre data-tb-block="code" data-language="python"><code>…</code></pre>`，
   已允许；内容必须是真能跑的片段或可复制的命令/配置，不放假代码。
3. **提示块**：`<aside class="tb-callout" data-tone="warn">…</aside>`，用于常见误区、
   安全警告、评审提醒。`data-tone` 目前在净化器白名单外，会被剥掉 → 在
   `contract/sanitize.py` 的 `ALLOWED_ATTRIBUTES["*"]` 增加 `data-tone`
   （纯展示标记，无脚本能力，属于白名单加法，不升契约版本）。
4. **对比表**：已有 `table`；重排后统一“对照型知识用表、过程型知识用图”。

分配（按实际需要，不是每课都塞）：

- 图：标准地图、安全标准族、功能安全、分层、设计方法、任务链、预言、SIL/HIL、
  实验设计、缺陷证据链、逃逸闭环、覆盖率、回归范围、认证路径、综合证据矩阵
- 代码块：实验设计（样本量/置信区间）、Flakiness（检测脚本）、回归（用例选择）、
  SIL/HIL（场景配置 + 实时预算）、任务链（注入点）、缺陷（证据单字段）、综合（矩阵）
- 提示块：每课至少 1 个（误区/风险/评审提醒），替换现在藏在正文里的同类段落

`tb depth` 的图示计数只看 `<figure>`/`table`，不受影响。

## 6. 方案：可验证性（引擎新增规则）

`quality/lint.py` 新增 `lint.lesson_order`（error）：

> 对每课，其概念的每个先修概念必须已被**同一课或更早的课**覆盖；否则报错并指出
> 缺失概念与所在课。

实现：按 `pack.lessons_in_order()` 建立 concept → 最早出现课序；逐课比较。
无课的先修概念跳过（已有 `concept.no_lesson` warning 覆盖）。

这样“重排是否真的更系统”从主观判断变成 `tb lint` 的硬门禁，作者每次重排都要过。

  新练习全部挂载）。
- `tb depth` → 0 error（新 SIL/HIL 课达到 L3：≥3,500 字、≥6 个 `<h2>`、≥1 图/表、≥2 练习）。

- `tb build` → 22 课全部产出，图片路径可解析，无外部 URL。
- 讲评：`tests/test_tutor_review.py` 断言讲评上下文不包含其他练习题干；
  `tests/test_tutor_review_service.py` 断言旧 `prompt_version` 缓存会重新生成。
- `tests/test_sanitize.py` 断言 `data-tone` 保留、`style`/事件属性仍被拒绝。
- `tests/test_quality_lint.py` 新增乱序课程包被 `lint.lesson_order` 拦下。
- 全量 `pytest` 不回归（基线 665 passed + 1 known failing，见下）。
- 学习数据：`/concepts`、`/today`、`/review` 仍显示 `test-strategy-inputs`、
  `risk-grading` 的掌握度与 3 张复习卡。
