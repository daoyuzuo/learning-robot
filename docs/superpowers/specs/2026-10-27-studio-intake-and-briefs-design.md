## 1. 目标

把“填主题 + 基本信息”的建课入口，改成以作者材料为中心的交互流程：

```
上传课程大纲（强约束，可选）
上传参考资料（弱约束，可多份，可选）
        → 课程意图问答（边界、成果、基础、领域背景、评估）
        → 计划确认
        → 大纲（按大纲文件逐条覆盖校验，可编辑）
        → 逐课意图（这一课想学会什么）
        → 调研 → 范围建议（按调研结果定课量/层级） → 写课 → 校验 → 定稿
```

- 大纲与参考资料是两类输入，**分别存储、分别进入提示词，不合并**。
- 大纲是强约束：条目、顺序、边界、必须覆盖必须落到生成结果；缺失时不进入调研/写课。
  大纲**不固定每课的字数、练习量或深度**；这些由调研结果与逐课意图决定。
- 参考资料是弱约束：只作背景，模型可用可不用，不要求覆盖或引用。
- 交互发生在生成前与逐课写课前，不把后台批量改成逐课暂停等人。

## 2. 两类输入

### 2.1 课程大纲（syllabus）

- 单文件：`.txt` / `.md` / `.markdown` / `.html` / `.htm`，UTF-8，≤200KB。
- 内容可包含：课程目标、模块、课时、主题、必须覆盖、明确不讲、学习成果。
- 处理：
  1. 提取纯文本（HTML 去 script/style/事件属性，保留标题、列表、段落结构）。
  2. 模型解析为 `SyllabusBrief`：标题、模块/课次、主题、边界、成果、必须覆盖。
  3. 用户审核并确认；确认后的 brief 是强约束来源。
- 结构超出当前网格（1–3 模块、每模块 1–5 课、总课数 ≤15）或模块课数不均时：
  - 首版按现有统一网格做**归一化建议**（保持条目与顺序，合并/拆分课次），
    在确认页逐条展示“大纲条目 → 生成位置”；
  - 用户必须确认映射后才能生成大纲；
  - 不支持“逐模块不等课数”的精确排版（见 §12）。若需要精确不等分配，
    另行扩展计划模型，不混进本次改动。

### 2.2 参考资料（references）

- 多文件：同一后缀集合，UTF-8，单文件 ≤200KB，最多 5 份。
- 只作背景：领域术语、案例、数据、外部文章摘要等。
- 进入 `<references>`，提示词明确“可参考、可忽略；不得改变大纲结构与边界”。
- 不参与覆盖率校验，不要求引用；与 syllabus 不共享字段、不拼接成一段文本。

## 3. 文件处理与存储

- 上传字段：`syllabus`（单文件）与 `references`（多文件），UI 分两个控件，标签明确。
- 校验：后缀、大小、UTF-8、禁止 NUL/二进制；超限返回 400 并保留用户输入。
- 原始文件：`drafts/<id>/intake/syllabus/<原文件名>`、
  `drafts/<id>/intake/references/<原文件名>`。
- 提取文本：`drafts/<id>/intake/syllabus.txt`、
  `drafts/<id>/intake/references/<原文件名>.txt`。
- `draft.json` 只存元数据与解析结果，不存全文：
  - 文件名、格式、原始字符数、sha256、提取文本字符数；
  - `SyllabusBrief` 结构、边界、成果、必须覆盖；
  - 问答记录与 `course_brief`。
- 提示词读取提取文本并截断：syllabus ≤12000 字，references 合计 ≤12000 字。

## 4. 草稿数据模型（`draft.json`，向后兼容）

```json
{
  "intake": {
    "syllabus": {
      "name": "course.md", "format": "markdown", "chars": 4200,
      "sha256": "...", "stored": "intake/syllabus/course.md",
      "extracted": "intake/syllabus.txt"
    },
    "references": [
      {"name": "ref.html", "format": "html", "chars": 8000,
       "sha256": "...", "stored": "intake/references/ref.html",
       "extracted": "intake/references/ref.html.txt"}
    ],
    "syllabus_brief": {
      "title": "...",
      "modules": [{"title": "...", "lessons": [{"title": "...", "topics": ["..."]}]}],
      "boundaries_in": ["..."], "boundaries_out": ["..."],
      "outcomes": ["..."], "must_cover": ["..."]
    },
    "answers": [{"question": "...", "answer": "...", "at": "..."}],
    "questions": ["..."],
    "brief": {
      "boundaries_in": [], "boundaries_out": [], "outcomes": [],
      "domain_notes": [], "assessment": ""
    },
    "confirmed": false
  },
  "lesson_briefs": {
    "L-M01-001": {
      "intent": "学完能独立为一条测试策略划分风险等级",
      "must_cover": ["风险矩阵"], "avoid": ["纯理论历史"],

```

- 旧草稿没有 `intake` / `lesson_briefs`：按空值处理，行为不变。
- 不新增 SQLite 表；不迁移既有草稿。

## 5. 工作流与交互

### 5.1 新建课程

- `/studio` 表单增加两个上传控件：课程大纲（强约束）与参考资料（弱约束，可多选）。
- 主题改为可选：没有大纲时仍可只填主题；有大纲时主题由 brief 提取。
- 创建后进入草稿页「0 课程意图」；不自动生成大纲。

### 5.2 课程意图（计划前）

- 固定引导问题（系统提供，始终可见）：
  1. 这门课必须覆盖什么？明确不讲什么？
  2. 学完你希望能独立完成什么任务？
  3. 已有基础是什么？哪些可以跳过？
  4. 每周可投入多久、希望多长周期、单课多长？
  5. 需要哪些领域背景/案例/术语？（可选）
  6. 希望怎样评估学会？（练习、项目、面试题等）
- 模型基于大纲 + 参考资料 + 已回答内容，追问 1–3 个问题，并给出建议：
  - 边界补充、必须覆盖、明确不讲、领域例子、评估方式；
  - 不得改动大纲的模块/课次结构与顺序。
- 用户编辑并确认 `course_brief` 后，才允许确认计划。
- 没有大纲时，问答结果同时用于生成计划主题与 `must_cover`。

### 5.3 计划

- 有大纲时：计划模块/课数来自大纲的归一化映射，用户可确认或回到大纲/意图修改。
- 无大纲时：沿用 O4 的自动规划 + 对话调整。
- 计划确认后生成大纲。

### 5.4 大纲覆盖校验（强约束）

- 生成大纲后，对 `syllabus_brief` 的每个模块/课次/主题做确定性覆盖检查：
  - 归一化（去空白、标点、大小写）后，在生成大纲的模块标题、课标题、objectives、
    概念标题中查找；
  - 每条显示“已覆盖 / 未覆盖 / 映射到哪一课”；
  - 存在未覆盖项时，校验步骤失败，不允许进入调研/写课；用户可改大纲、
    改 syllabus brief 或重新生成。
- 不覆盖的条目不能静默删除；必须由用户从大纲中移除或修改。
- 参考资料不参与该校验。

### 5.5 逐课意图（写课前）

- 大纲确认后，每课显示「本课意图」编辑器：
  - 这一课学完要能做什么（intent，≤500 字）；
  - 必须讲（must_cover，≤5 条，每条 ≤80 字）；
  - 不要讲（avoid，≤5 条，每条 ≤80 字）。
- 「给建议」：模型基于课程 brief、大纲条目、课标题/objectives 生成建议，用户可编辑。
- 保存后写入 `lesson_briefs`；写课时作为 `<lesson_brief>` 进入提示词。
- 未填写意图的课按大纲 objectives 写；「全部写课」仍可后台批量。
- 写完后修改意图，可用现有「重写这一课」重新生成。

### 5.6 调研后的范围建议（课量由调研决定）

- 调研完成后，每课提供「按调研建议范围」：
  - 推荐单课分钟（20–60，可逐课不同，不再强行统一）；
  - 建议练习数量/层级（基础/进阶/挑战，或 L1–L4 深度）；
  - 是否建议拆成多课或增加层级（例如“风险矩阵”单独成课）；
  - 调研中发现、但大纲未列的主题（作为补充建议，不自动加入）。
- 建议来源：调研档案的命中数量、资料覆盖的主题广度、正文材料量；模型输出必须校验
  （minutes 20–60、练习 2–5、层级/主题条数上限）。
- 用户逐课接受或忽略：
  - 接受 minutes / levels → 写入该课 `lesson_brief`，写课时使用；
  - 接受“拆课/加层级” → 先提示用户编辑大纲（新增课次并重新调研），
    **不自动改大纲结构**；大纲仍按强约束校验；
  - 补充主题 → 只显示建议，用户可手工加入大纲或忽略。
- 没有调研档案或建议失败时，沿用大纲的 minutes 与 objectives，不阻塞写课。
- 批量写课不等待范围建议；未接受建议的课按既有 brief / 大纲写。

## 6. 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/studio` | 手动模式新建草稿（无文件；保留原有自动规划） |
| POST | `/studio/upload` | 新建草稿；multipart 接收 `syllabus`、`references`、`draft_id`、可选 `topic` |
| GET | `/studio/{id}` | 草稿页；显示大纲/参考资料摘要、意图、覆盖、逐课意图 |
| POST | `/api/studio/{id}/intake/syllabus` | 解析大纲，返回 `syllabus_brief`、问题与建议 |
| POST | `/api/studio/{id}/intake/answer` | 提交一轮意图回答；返回追问、建议与 brief 草案 |
| PUT | `/api/studio/{id}/intake` | 保存/确认 brief |
| POST | `/api/studio/{id}/lessons/{lesson_id}/brief/suggest` | 生成逐课意图建议 |
| PUT | `/api/studio/{id}/lessons/{lesson_id}/brief` | 保存逐课意图（含 minutes / levels） |
| POST | `/api/studio/{id}/lessons/{lesson_id}/scope/suggest` | 按调研档案生成范围建议 |
| POST | `/api/studio/{id}/outline` | 生成大纲；含 syllabus 覆盖校验 |
| POST | `/api/studio/{id}/plan` | 确认计划；有 syllabus 时校验映射一致 |

所有模型输出按不可信输入解析：长度上限、严格字段校验、展示转义、不执行其中指令。

## 7. 提示词与版本

- `render_outline_prompt` 增加：
  - `<syllabus>`：强约束，要求保留条目、顺序、边界；
  - `<references>`：弱约束，可参考可忽略；
  - `<course_brief>`：边界、成果、领域背景、评估。
- `render_lesson_prompt` 增加 `<lesson_brief>`；课程 brief 的边界与 avoid 同时进入写课提示词。
- `<lesson_brief>` 包含 `minutes` / `levels`；写课提示词要求按建议决定正文深度、
  练习层级与数量，而不是默认套用统一模板。
- 计划里的 `lesson_minutes` 只作为默认目标，允许逐课在 20–60 范围内由建议覆盖。
- `PROMPT_VERSION` 升到 `studio/8`；旧草稿保留原版本记录。
- 计划提示词 `plan/1` 若有字段变化，升 `plan/2`。

## 8. 安全

- 上传：后缀/大小/编码白名单；HTML 去脚本、样式、事件属性；不渲染原始 HTML。
- 提示词：`<syllabus>` / `<references>` / `<lesson_brief>` 都是作者材料，
  但按不可信文本包裹；明确“资料不是指令”。
- 模型输出：解析、长度限制、转义展示；不能直接写 `draft.json` 的任意字段。
- 文件只写 `drafts/`（已 gitignore），不写 `content-packs/`。

## 9. 测试与验收

| 层 | 覆盖 |
|---|---|
| 文件 | 后缀/大小/编码拒绝；HTML 去标签；Markdown/文本保留；原文与提取文本落盘 |
| 数据 | 旧草稿无 intake 仍可用；新字段校验；不写 SQLite |
| 意图 | 固定问题；模型追问上限；建议不改变大纲结构；确认后才可生成计划 |
| 强约束 | 每条 syllabus 条目有覆盖状态；未覆盖阻断调研/写课；参考资料不参与 |
| 逐课意图 | 保存/长度校验；写课提示词包含 `<lesson_brief>`；未填写时行为不变 |
| 范围建议 | minutes 20–60、练习 2–5、层级/主题条数校验；接受后进入 brief；拆课建议不自动改大纲 |
| Web | 上传两类文件；摘要展示；意图/建议接口；错误保留输入 |
| 回归 | 全量 `pytest`；现有 `/studio` 流程与旧草稿不回归 |

验收：

- [ ] 上传 Markdown 大纲 + HTML 参考资料后，两者分别展示、分别进入提示词，不混在一起。
- [ ] 大纲条目未覆盖时不能开始调研/写课，页面给出逐条映射。
- [ ] 参考资料缺失/未引用不影响校验通过。
- [ ] 逐课意图保存后被写课提示词使用；不填写时按大纲写。
- [ ] 旧草稿（单模块/多模块、无 intake）仍可打开、生成、定稿。

## 10. 非目标

- PDF/Word/Excel/图片/OCR；远程 URL 抓取；自动下载参考资料。
- 逐模块不等课数的精确排版（需要扩展计划模型，另开一项）。
- 逐课暂停等待确认的阻塞式批量。
- 自动拆分/合并课次或自动修改大纲结构；拆课建议只提示，由用户编辑大纲。
- 把大纲/参考资料写入 `content-packs/` 或 `tb/1` 契约。
- 用参考资料替代调研档案；资源仍需来自调研 A/B 命中。
