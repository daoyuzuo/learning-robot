# P3.1 内容生产工作台设计（Content Studio）

- 状态：Approved，2026-10-25
- 范围：主题 → 大纲 → 调研 → 课程/练习/资源 → 门禁 → 定稿，全部在前端完成
- 上游：[P1 教学引擎设计](2026-10-24-teaching-engine-design.md)、[P2.2 追问](2026-10-25-p2.2-tutor-design.md)
- 路线图：[ROADMAP](../../ROADMAP.md)

---

## 1. 目标

把"从主题到可学习内容包"固化成前端工作台，让作者不必进项目目录跑命令。

**输入**：主题、目标级别、课数、每课检索预算（默认 20）。
**输出**：`content-packs/<id>/`，普通 `tb/1` 包，引擎零改动。
**运行方式**：`tb serve` 打开 `/studio`，全程页面操作。

## 2. 非目标

- 批量重生成、`tb migrate`、多模块包。
- 自动发布、多人协作、草稿版本历史。
- 在页面里保存 API 密钥（仍走环境变量）。
- 修改已有 `content-packs/` 里的包（只新增）。

## 3. 决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 交互形态 | 前端工作台，CLI 可选 | 用户目标是"全部在前端完成" |
| 检索后端 | DeepSeek Search / Fetch API | 与对话同一 key；结果自带 authority |
| 检索预算 | 每课默认 20 次，可配 | 先调研充分再写 |
| 大纲编辑 | contenteditable 直接改渲染结果，保存时净化 | 用户明确要求 |
| 大纲格式 | HTML，不用 Markdown | 同上 |
| 调研档案 | 只读（JSON + HTML 视图） | 它是来源证据，不允许改 |
| 长任务 | 后台线程 + 状态轮询 | 调研与写课需要几十秒到几分钟 |
| 状态存储 | `drafts/<id>/draft.json` | 简单、可人工检查；重启后可恢复 |
| 测试 | 默认全假；`TESTBRIDGE_LIVE=1` 才真实调用 | 不花冤枉钱 |

## 4. 页面

```
/studio                草稿列表 + 新建表单
/studio/<id>           工作区：五个步骤卡片
```

步骤卡片与动作：

| 步骤 | 动作 | 产出 |
|---|---|---|
| 1 大纲 | 生成 / 重新生成 / **直接编辑** / 保存 | `pack.yaml`、`concepts.yaml`、`module.yaml`、`outline.html` |
| 2 调研 | 按课启动（可单课） | `research/<lesson>.json` + `.html` |
| 3 写课 | 按课启动（可单课） | 课程 HTML、`exercises.yaml`、`resources.yaml`、`module.yaml` 更新 |
| 4 校验 | 运行 | 离线 validate 结果 + 资源可达性结果 |
| 5 定稿 | 运行 | 拷贝到 `content-packs/<id>` |

页面每 2 秒轮询 `/api/studio/<id>`，运行中的步骤显示进度文案（如"检索 7/20"）。

## 5. 目录与状态

```
drafts/<id>/
  draft.json
  pack.yaml
  concepts.yaml
  exercises.yaml
  resources.yaml
  outline.html
  modules/M01/
    module.yaml
    lessons/<lesson-id>.html
  research/
    <lesson-id>.json
    <lesson-id>.html
```

`drafts/` 加入 `.gitignore`。

`draft.json`：

```json
{
  "schema": "studio/1",
  "id": "ros2-executor",
  "topic": "ROS 2 执行器与回调组",
  "level": "L3",
  "lesson_count": 3,
  "searches_per_lesson": 20,
  "model": "deepseek-chat",
  "prompt_version": "studio/1",
  "search_backend": "auto",
  "created_at": "2026-10-25T12:00:00+00:00",
  "updated_at": "2026-10-25T12:10:00+00:00",
  "usage": {"searches": 0, "llm_calls": 0},
  "steps": {
    "outline": {"status": "pending", "error": null, "at": null},
    "research": {"L-EXEC-001": {"status": "pending", "queries": 0, "hits": 0, "backend": "..."}},
    "lessons": {"L-EXEC-001": {"status": "pending", "error": null}},
    "validation": {"status": "pending", "issues": []},
    "promote": {"status": "pending", "error": null}
  }
}
```

状态值：`pending | running | done | failed`。服务启动时把所有 `running` 改为
`failed`，错误文案 `interrupted`。

写入一律"临时文件 + replace"，避免半截 JSON。

## 6. 模块边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| `studio/store.py` | `draft.json` 与草稿文件读写、状态更新 | 不调模型 |
| `studio/jobs.py` | 线程执行、单草稿互斥、状态机 | 不含业务规则 |
| `studio/search.py` | DeepSeek Search/Fetch 客户端、authority→trust | 不选查询 |
| `studio/prompts.py` | 大纲与写课提示词、输出契约 | 不写文件 |
| `studio/outline.py` | 大纲 JSON → 契约文件 + `outline.html` | 不生成正文 |
| `studio/research.py` | 查询编排、去重、档案存档 | 不写课程 |
| `studio/lessons.py` | 模型输出 → 课程 HTML/练习/资源，合并 YAML | 不做最终校验 |
| `studio/promote.py` | validate + 资源核验 + 拷贝 | 不生成内容 |
| `web/studio.py` | 路由与模板上下文 | 不含业务规则 |

`studio/` 不 import `mastery`、`schedule`、`learning`、`evidence`。

## 7. 检索

**端点**（与 P2.2 共用 `TutorConfig`）：

- `POST {base_url}/tools/search`，body `{query, count, need_content: true}`
- `POST {base_url}/tools/fetch`，body `{url}`，仅在 `content` 为空时使用

`base_url` 形如 `https://api.deepseek.com/v1`。

**映射**：`authority >= 3 → A`、`2 → B`、`1 → C`、`0/-1 → D`。C/D 只作提示，不写入 `resources.yaml`。

**查询编排**（每课）：

1. 大纲里该课的 `research_queries` 原样执行。
2. 追加 `"<课标题>"` 与 `"<课标题>" site:docs.ros.org OR site:docs.ros2.org`。
3. 追加每个概念的标题。
4. 按 `searches_per_lesson` 截断，按 URL 去重。

**重试**：429 / 5xx / 超时退避 1 秒重试一次，仍失败记该查询失败并继续。

## 8. 大纲生成

模型输出 JSON：

```json
{
  "module_title": "ROS 2 执行器与回调组",
  "concepts": [
    {"id": "executor-basics", "title": "执行器基础", "domain": "ros2",
     "target_level": "L2", "prerequisites": [], "weight": 1.0,
     "evidence_criteria": [{"id": "EV-EXEC-DEFINE", "description": "...", "level": "L1"}]}
  ],
  "lessons": [
    {"id": "L-EXEC-001", "title": "单线程执行器", "minutes": 20,
     "objectives": ["..."], "exercise_intents": ["..."],
     "research_queries": ["ROS 2 executors"]}
  ]
}
```

服务端校验：

- `concepts[].id`、`lessons[].id` 匹配 `^[A-Za-z][A-Za-z0-9-]*$`。
- 概念先修引用存在；课程引用概念存在。
- `lessons` 数量等于 `lesson_count`；`lesson_count` 在 1–5 之间。

落盘：`pack.yaml`（`fixture: false`）、`concepts.yaml`、`modules/M01/module.yaml`、
`outline.html`（人类可读的计划，可编辑）。

**手工编辑后的一致性**：保存大纲时按新的课程 id 重新计算 `steps.research` /
`steps.lessons` 的键——已存在且仍在的课保留状态，新增课置 `pending`，
被删掉的课连同其文件一起从状态中移除（已生成的 `research/` 与课程文件保留在磁盘，不删除）。

## 9. 写课生成

输入：该课大纲段 + 概念表 + 调研档案（hits 的 title/url/authority/summary/content 截断）。

模型输出 JSON：

```json
{
  "manifest": {"title": "...", "minutes": 20, "objectives": ["..."]},
  "html": "<article class=\"tb-lesson\">...</article>",
  "exercises": [ ... tb/1 exercise ... ],
  "resources": [ ... tb/1 resource ... ]
}
```

服务端规则：

- 课程 id 取大纲；manifest 的 `concepts` 必须属于本包概念。
- 练习 id、资源 id 全局唯一（跨草稿已有文件检查）。
- 资源只接受 A/B 级来源；`last_verified` 填生成日期。
- `html` 保存前走 `sanitize_fragment`，禁止脚本/iframe/事件属性。
- 先写临时文件，全部成功后再替换；单课失败保留其它课成果。

## 10. 门禁

| 关卡 | 规则 | 失败 |
|---|---|---|
| 生成 | JSON 可解析成契约对象 | 带错误重试 1 次，仍失败记 failed |
| 校验 | `validate_pack(drafts/<id>)` 0 error | 阻断定稿；warning 列出 |
| 资源 | 每个资源 URL `GET` 返回 < 400 | 阻断定稿（`--skip-verify` / 页面勾选可跳过，但记录警告） |
| 定稿 | `content-packs/<id>` 不存在 | 阻断（页面提供"覆盖"开关） |

定稿只拷贝内容文件：`pack.yaml`、`concepts.yaml`、`exercises.yaml`、
`resources.yaml`、`widgets.yaml`（若存在）、`modules/`、`assets/`（若存在）。
`draft.json`、`research/`、`outline.html` 不进入内容包。

## 11. API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/studio` | 列表 |
| POST | `/studio` | 新建（表单）并启动大纲 |
| GET | `/studio/<id>` | 工作区页面 |
| GET | `/api/studio/<id>` | 状态 JSON（轮询） |
| POST | `/api/studio/<id>/outline` | 重新生成大纲 |
| PUT | `/api/studio/<id>/outline` | 保存编辑后的 HTML |
| POST | `/api/studio/<id>/research` | 启动调研（可带 `lesson_id`） |
| POST | `/api/studio/<id>/lessons` | 启动写课（可带 `lesson_id`） |
| POST | `/api/studio/<id>/validate` | 校验 + 资源核验 |
| POST | `/api/studio/<id>/promote` | 定稿（`force`、`skip_verify`） |

错误码：`404 draft_not_found`、`409 step_running`、`400 invalid_request`、
`502 upstream`、`503 tutor_disabled`。

## 12. 失败处理

| 场景 | 行为 |
|---|---|
| 未配置模型 | 页面顶部提示缺哪些环境变量，所有动作禁用 |
| 单课调研失败 | 记 failed + 错误，其它课继续 |
| 单课写课失败 | 同上；已生成的课保留 |
| 进程重启 | `running` 一律改 `failed(interrupted)`，可重跑 |
| 磁盘写入失败 | 步骤 failed，原文件不动 |
| 定稿覆盖 | 仅在显式勾选"覆盖"时允许 |

## 13. 安全

- 密钥只从环境变量读，不落盘、不回显、不写日志。
- `outline.html` 保存时经 `sanitize_fragment`，标签白名单与内容包一致。
- 模型输出按不可信输入处理：先解析、再净化、后落盘。
- 前端不引入外部脚本（CSP `script-src 'self'`）。

## 14. 测试

**默认（不联网）**：假 `LlmClient` + 假 `SearchProvider`。

| 层 | 覆盖 |
|---|---|
| store | 读写、原子替换、重启把 running 改 failed |
| jobs | 同草稿互斥、失败记录、inline 模式 |
| search | authority→trust、请求体、重试、错误映射 |
| outline | JSON 校验、ID 规则、文件落盘、非法输入报错 |
| research | 查询编排、去重、预算截断、单查询失败继续 |
| lessons | 输出解析、净化、ID 唯一、YAML 合并、单课失败隔离 |
| promote | 三道门禁、覆盖开关、拷贝结果 |
| web | 列表/新建/状态/保存大纲/启动任务/轮询 |

**真实调用**：`tests/test_studio_live.py`，`TESTBRIDGE_LIVE=1` 时运行，标记 `live`；
默认 pytest 配置排除该标记。

## 15. 验收

- 全程页面完成：新建 → 编辑大纲 → 调研 → 写课 → 校验 → 定稿。
- 定稿后的包能通过 `tb validate`，并在 `/lesson/<id>` 正常打开。
- 引擎核心（mastery/schedule/evidence）无改动。
- 默认 `pytest` 全绿且不联网；现有 321 个测试不回归。
- 真实调用测试可通过 `TESTBRIDGE_LIVE=1` 手动执行。

## 16. 成本

- 检索：每课 20 次 × $0.00075 ≈ $0.015。
- 模型：每课约 1–2 万 token，按 DeepSeek 价格估算约 ¥0.1–0.3。
- 单包（3 课）总成本约 ¥1 以内。

## 17. 风险

| 风险 | 取舍 |
|---|---|
| 模型产出质量不稳 | 大纲人工确认；调研档案作为依据；校验器兜底 |
| contenteditable 改坏结构 | 保存时净化；失败可重新生成大纲 |
| 长任务体验 | 状态轮询 + 单课可单独重跑 |
| 检索结果质量 | authority 分级；只允许 A/B 进资源 |
| 费用不可见 | `draft.json` 记录检索次数与模型调用次数 |
