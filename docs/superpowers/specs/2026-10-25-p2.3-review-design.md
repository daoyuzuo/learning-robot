# P2.3 答后讲评与参考评分设计

- 状态：Approved，2026-10-25
- 范围：作答后按需请求 AI 讲评；有 rubric 的题型附带参考评分，记 `llm_review`，不参与掌握度
- 上游：[P1 教学引擎设计](2026-10-24-teaching-engine-design.md)、[P2 学习闭环](2026-10-25-p2-learning-loop-design.md)、[P2.2 追问](2026-10-25-p2.2-tutor-design.md)

---

## 1. 背景

P2.2 解决了“看不懂能问”，但没有解决“做完题不知道为什么错”。现有反馈只有一句固定文案（“再想想。”），简答题只有“关键点不足”，自评没有任何外部参照。

同时，关键词判分对“用自己的话解释”这类题误判明显，需要一个人工之外的参照。

## 2. 目标

1. 提交后可点一次按钮，得到针对**本次作答**的讲评。
2. 有 rubric 的题型（`short_answer`、`self_assess`）附带逐维度参考评分。
3. 参考评分记入证据账本，但**不影响**掌握度、复习、readiness、今日计划。
4. 同一作答重复点击不重复调用模型。

## 3. 非目标

- 产出物（artifact）自动评审。
- 内容更新后自动重评。
- 批量讲评、跨作答对比。
- 刷新页面后回显历史讲评（P2.4）。
- 把参考分纳入分数计算。

## 4. 决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 触发方式 | 提交后手动按钮 | 省钱、不打断做题节奏 |
| 讲评范围 | 所有题型 | 答对也想听“为什么对” |
| 参考评分范围 | 仅 `short_answer` / `self_assess` | 选择题判分已无歧义 |
| 记账方式 | 新 evidence kind `llm_review` | 现有 mastery/BKT/FSRS 只认已知 kind，天然隔离 |
| 缓存 | `exercise_review` 按 `evidence_id` 主键 | 避免重复付费；`refresh` 可强制重算 |
| 上下文 | 与追问分开构造 | 讲评必须含答案，追问必须不含 |

## 5. 架构

```
POST /api/review {evidence_id, refresh}
      │
      ▼
TutorService.review(evidence_id, refresh=False)
  ├─ EvidenceStore.get(evidence_id)         # 新方法
  ├─ 校验：存在、learner 匹配、kind ∈ {exercise_attempt, self_assess}
  ├─ ExerciseReviewStore.get(evidence_id)   # 缓存命中且未 refresh → 直接返回
  ├─ build_review_context(...)              # 含答案、解析、rubric、学习者的作答
  ├─ LlmClient.complete(REVIEW_PROMPT, ...)
  ├─ parse_review(...)                      # 过滤 rubric 维度、夹取分数
  ├─ ExerciseReviewStore.put(...)
  └─ 有 rubric 且有参考分时：append llm_review + LearningService.record
```

### 5.1 模块边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| `tutor/review.py` | 讲评上下文、提示词、解析 | 不读写数据库 |
| `tutor/review_store.py` | `exercise_review` 缓存表 | 不生成讲评 |
| `tutor/service.py` | 编排、缓存判断、证据追加 | 不做页面 |
| `evidence/store.py` | 新增 `get(event_id)` 与 `list(kind=...)` | 不判断学习语义 |

## 6. 上下文与提示词

**包含**：本课正文与概念（复用 `build_context`）、练习题干与选项、学习者的实际作答、正确答案、`explanation`、rubric 维度与权重。

**提示词要求**：先结论后理由；指出具体错在哪一步；不臆造 rubric 之外维度；只输出 JSON。

输出契约：

```json
{
  "verdict": "correct | partial | incorrect",
  "explanation": "字符串",
  "strengths": ["..."],
  "gaps": ["..."],
  "rubric": [{"dimension": "机制", "met": true, "comment": "..."}],
  "suggested_score": 0.6
}
```

解析规则：

- `rubric` 只保留题干 rubric 中真实存在的维度，按题干顺序排序。
- `suggested_score` 夹取到 `[0, 1]`；没有 rubric 或缺失时为 `None`。
- JSON 解析失败：整段文本作为 `explanation`，`verdict="partial"`，无参考分。
- `strengths` / `gaps` 各最多 3 条。

## 7. 数据模型

```sql
CREATE TABLE IF NOT EXISTS exercise_review (
  evidence_id     TEXT PRIMARY KEY,
  learner_id      TEXT NOT NULL,
  lesson_id       TEXT NOT NULL,
  exercise_id     TEXT NOT NULL,
  verdict         TEXT NOT NULL,
  explanation     TEXT NOT NULL,
  strengths_json  TEXT NOT NULL DEFAULT '[]',
  gaps_json       TEXT NOT NULL DEFAULT '[]',
  rubric_json     TEXT NOT NULL DEFAULT '[]',
  suggested_score REAL,
  model           TEXT NOT NULL,
  prompt_version  TEXT NOT NULL,
  created_at      TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_review_exercise
  ON exercise_review(learner_id, exercise_id);
```

参考评分事件：

```yaml
kind: llm_review
concept_ids: <exercise.concepts>
lesson_id: <event.lesson_id>
exercise_id: <event.exercise_id>
outcome: submitted
score: <suggested_score>
max_score: 1.0
source: tutor
payload:
  evidence_id: <被讲评的作答>
  model: <config.model>
  prompt_version: review/1
  rubric: [...]
```

重新生成时，新的 `llm_review` 通过 `supersedes` 指向同一作答的旧 `llm_review`（用 `EvidenceStore.list(kind="llm_review")` 查找最新一条）。

## 8. API

`POST /api/review`

```json
{ "evidence_id": "abc", "refresh": false }
```

成功（200）：

```json
{
  "verdict": "partial",
  "explanation": "...",
  "strengths": ["..."],
  "gaps": ["..."],
  "rubric": [{"dimension": "机制", "met": true, "comment": "..."}],
  "suggested_score": 0.6,
  "model": "deepseek-chat",
  "cached": false,
  "saved": true
}
```

| 情况 | 状态码 | code |
|---|---|---|
| 正常 | 200 | — |
| evidence 不存在或 learner 不符 | 404 | `evidence_not_found` |
| kind 不支持 / exercise 不存在 | 400 | `unsupported_evidence` |
| 未配置模型 | 503 | `tutor_disabled` |
| 上游错误 | 502 | `tutor_upstream` |
| 上游超时 | 504 | `tutor_timeout` |

## 9. 页面

`web/static/tb-runtime.js` 在练习提交成功后，向该练习表单追加「让 AI 讲讲」按钮（仅在追问已配置时）。点击后：

- 按钮禁用，显示“正在讲评…”。
- 结果渲染在表单内 `.tb-review` 区块：结论徽章、讲评正文、优点/差距列表、rubric 表格、参考分（标注模型名）。
- 出错时在区块内显示错误文本，不弹窗。

不新增模板：按钮由 JS 注入，避免服务端需要知道每条 evidence。

## 10. 错误处理

| 场景 | 行为 |
|---|---|
| 缓存存在且 `refresh=false` | 直接返回缓存，不调模型 |
| 模型返回非 JSON | 降级为讲评文本，`verdict=partial`，无参考分 |
| 参考分缺失 | 不写 `llm_review` |
| 证据写入失败 | 讲评仍返回，`saved=false` |
| 缓存写入失败 | 讲评仍返回，`cached=false` |

## 11. 不变量

- `llm_review` 不改变 `mastery_state`、`review_state`、`readiness`：`mastery/rule.py` 的 `KIND_WEIGHTS` 不包含它，`replay_bkt` 只吃 `exercise_attempt`，`rebuild_state` 的复习重放只看 `exercise_attempt`。
- 讲评事件本身不触发新的 FSRS 卡。
- 追问上下文仍不含答案（回归测试保留）。

## 12. 测试

| 层 | 覆盖 |
|---|---|
| evidence | `get` 命中/未命中；`list(kind=...)` 过滤 |
| review 上下文 | 含答案、解析、学习者作答；不含其它题 |
| parse | 合法 JSON；非法 JSON 降级；rubric 维度过滤与排序；分数夹取 |
| review store | 写入/读取/覆盖 |
| service | ownership；kind 校验；缓存命中不调模型；refresh 重算；llm_review 追加；mastery 不变 |
| web | 200 / 404 / 400 / 503 / 502 / 504；缓存标志 |

全部使用假 client，不联网。

## 13. 验收

- `pytest` 全绿，现有 266 个测试无回归。
- 讲评后 `mastery`、`readiness`、`review_state` 与讲评前完全一致。
- evidence 表只新增 `llm_review` 一类记录。
- `/progress` 能看到 `llm_review` 行，分数标为参考。

## 14. 风险

| 风险 | 取舍 |
|---|---|
| 模型评分与关键词判分冲突 | 两者并存、分别标注；参考分不进掌握度 |
| 讲评内容误导 | 讲评基于课程答案与解析，要求引用具体步骤 |
| 成本 | 手动触发 + 按 evidence 缓存 |
| 学生先看讲评再重做 | 讲评绑定已提交的 evidence，不影响新一次作答的判分 |
