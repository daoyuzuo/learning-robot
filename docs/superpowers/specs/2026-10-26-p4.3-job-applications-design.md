# P4.3 求职管理设计（Job Applications）

- 状态：Design approved，2026-10-26；实施中
- 分支：`p4.3-job-applications`
- 上游：[P1 教学引擎](2026-10-24-teaching-engine-design.md)、[P2 学习闭环](2026-10-25-p2-learning-loop-design.md)、[P4.2 公司/JD 匹配](2026-10-26-p4.2-company-jd-design.md)
- 路线图：[ROADMAP](../../ROADMAP.md)

## 1. 目标

把求职过程本身变成可追踪的本地记录：

```
创建投递 → 更新状态/笔记 → 设置下一步动作与日期
        → /applications 显示到期跟进
        → 面试后写复盘笔记
```

- 单用户、本地 SQLite；不做多用户、云同步、招聘网站集成。
- 纯 CRUD + 跟进提醒；不依赖 LLM，不改引擎。
- 与 P4.2 的目标 JD 并列存在：JD 决定学什么，投递记录决定求职节奏。

## 2. 非目标

- 自动投递、招聘网站爬虫、邮件/日历集成。
- 多用户、权限、共享。
- 简历生成、公司情报采集。
- 把投递记录写进能力账本或影响 readiness/mastery。
- 面试会话与投递记录的强关联（v1 只在笔记里写，不做外键）。

## 3. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 一条记录 = 一次“公司 + 岗位”的投递 | 同一公司多岗位可分开跟踪 |
| D2 | 状态枚举自由流转，不做严格状态机 | 真实求职会来回跳（面试后又被拒、重新联系） |
| D3 | 不提供删除；用 `withdrawn` 结束 | 保留复盘历史；避免误删 |
| D4 | 跟进日期 `next_action_at` 可选；到期项只在 `/applications` 聚合 | 不改 planner/`/today`，引擎零改动 |
| D5 | 笔记纯文本、转义展示 | 可能含公司机密/个人信息，不做 HTML |
| D6 | 与 P4.2 的 `target_jd` 不建外键 | 投递可能针对多个岗位；JD 是“当前目标”，不是投递属性 |

## 4. 数据模型

### 4.1 `application`（同一 SQLite，新表）

```sql
CREATE TABLE IF NOT EXISTS application (
  id              TEXT PRIMARY KEY,
  learner_id      TEXT NOT NULL DEFAULT 'local',
  company         TEXT NOT NULL,
  role            TEXT NOT NULL,
  source          TEXT NOT NULL DEFAULT '',
  status          TEXT NOT NULL DEFAULT 'draft',
  applied_at      TEXT,
  next_action_at  TEXT,
  next_action     TEXT NOT NULL DEFAULT '',
  notes           TEXT NOT NULL DEFAULT '',
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_application_learner
  ON application(learner_id, updated_at);
CREATE INDEX IF NOT EXISTS idx_application_due
  ON application(learner_id, next_action_at);
```

- 状态：`draft | applied | screening | interviewing | offer | rejected | withdrawn`。
- 结束态：`offer | rejected | withdrawn`；结束态不再计入“到期跟进”，但仍可编辑/改状态。
- 日期字段为 `YYYY-MM-DD` 或空。

### 4.2 对象

```python
@dataclass(frozen=True)
class Application:
    id: str
    learner_id: str
    company: str
    role: str
    source: str = ""
    status: str = "draft"
    applied_at: str | None = None
    next_action_at: str | None = None
    next_action: str = ""
    notes: str = ""
    created_at: str = ""
    updated_at: str = ""
```

## 5. 校验与存储

- `company` 1–200 字符；`role` 1–200；`source` ≤ 100；`next_action` ≤ 200；`notes` ≤ 5,000。
- `status` 必须属于枚举；非法值 → `ApplicationError`。
- 日期必须能 `date.fromisoformat` 解析；空字符串按 `None`。
- 文本经 `safe_text`（UTF-8 replace）并在写入前裁剪到上限。
- `ApplicationStore.create(...)` 生成 `uuid4().hex`、`created_at/updated_at=iso(utcnow())`。
- `ApplicationStore.update(app_id, **changes)` 只接受白名单字段；不存在 → `ApplicationError`；校验后整行更新并刷新 `updated_at`。
- `list(status=None)` 按 `updated_at DESC, id` 排序；`due(on_date)` 返回
  `next_action_at <= on_date` 且状态不在结束态的记录，按 `next_action_at, company` 排序。
- `counts()` 返回每个状态的数量（含 0）。

## 6. 页面与接口

| 路由 | 说明 |
|---|---|
| `GET /applications` | 列表、状态筛选、到期跟进、创建表单、状态计数 |
| `POST /applications` | 创建，303 到详情 |
| `GET /applications/{id}` | 详情 + 编辑表单 |
| `POST /applications/{id}` | 更新字段/状态/笔记，303 到详情 |
| `POST /applications/{id}/withdraw` | 快捷置为 `withdrawn`，303 回详情 |

- `web/applications.py`，用 `mount_applications(app, templates, *, store)` 追加挂载。
- 模板：`applications.html`（列表 + 到期 + 创建）、`application_detail.html`（详情 + 编辑）。
- 导航新增“求职”。
- 写操作成功后 303（PRG）；校验失败渲染 400 并保留用户输入。

## 7. 页面内容

**列表 `/applications`：**
- 顶部：状态计数（草稿/已投/面试中/Offer/已结束）。
- “到期跟进”：到期项表格（公司、岗位、动作、日期、状态）。
- 全部投递：表格（公司、岗位、状态、投递日期、下一步、更新日期），可按状态筛选。
- 创建表单：公司、岗位、渠道、状态（默认 draft）、投递日期、下一步、跟进日期、笔记。

**详情 `/applications/{id}`：**
- 只读信息 + 编辑表单（同字段）。
- `withdraw` 按钮（非结束态时显示）。
- 笔记多行文本，转义展示。

## 8. 模块边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| `src/testbridge/career/applications.py` | `Application`、状态/日期校验、`ApplicationStore` | 不渲染页面、不调用 LLM |
| `web/applications.py` | 路由、表单解析、模板上下文 | 不写 SQL |
| `career/matching.py` / `career/jd.py` | P4.2 既有职责 | 不感知投递记录 |

- 引擎模块（`mastery`、`schedule`、`evidence`、`contract`、`learning`）不得 import `career`（沿用 P4.2 的 AST 边界测试）。
- 投递记录不影响 readiness、mastery、planner。

## 9. 安全

- 所有字段按纯文本存储与转义展示；不使用 `|safe`。
- 长度上限 + 日期解析；非法输入 400。
- 本地 SQLite；不发送到任何外部服务。
- 无 LLM 调用。

## 10. 测试

**单元**

- 创建/读取往返；空公司/岗位拒绝；非法状态；非法日期；超长字段裁剪。
- 更新白名单字段；不存在 ID；`updated_at` 刷新。
- `list` 排序/筛选；`due` 排除结束态与未来；`counts`。
- `withdraw` 幂等。

**Web**

- 空列表与创建表单；创建 → 303 → 详情；编辑 → 303；校验失败 400 且保留输入。
- 到期跟进区；状态筛选；`withdraw`；字段转义；导航。
- 创建后 `due` 在当天出现；改为 `offer` 后从到期区消失。

**回归**

- 全量 `pytest` 全绿；两个现有包 `tb validate` 0/0。
- 引擎不 import `career` 的边界测试继续通过。
- 默认测试不联网。

## 11. 验收

- [ ] `/applications` 可创建、列表、筛选、编辑、撤回
- [ ] 到期跟进在 `/applications` 正确显示，结束态/未来项不显示
- [ ] 笔记与公司/岗位文本正确转义
- [ ] 非法状态/日期/空必填被拒绝（400），输入保留
- [ ] 全量测试通过，两个包 `tb validate` 0/0
- [ ] 引擎模块不 import `career`；readiness/mastery 不受投递记录影响

## 12. 风险

| 风险 | 缓解 |
|---|---|
| 误删投递记录 | 不提供删除；用 withdrawn |
| 个人信息/公司机密外泄 | 本地 SQLite、无外部调用、纯文本 |
| 日期格式混乱 | 统一 `YYYY-MM-DD`，解析失败即 400 |
| 状态被随意改坏 | 枚举校验；不做严格状态机（D2） |
| 范围蔓延到日历/邮件 | 明确非目标；跟进只在页面内聚合 |
