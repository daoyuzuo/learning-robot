# P3.5 内容演进设计（Batch Regeneration & Version Compare）

- 状态：Implemented，2026-10-26
- 范围：跨草稿选课重生成、prompt 版本记录、旧/新快照与质量对比
- 上游：[P3.1 内容工作台](2026-10-25-p3.1-content-studio-design.md)、[P3.2 质量门禁](2026-10-25-p3.2-quality-gates-design.md)、[P3.4 多模块与批量](2026-10-25-p3.4-multi-module-batch-design.md)
- 路线图：[ROADMAP](../../ROADMAP.md)

---

## 1. 目标

P3.5 让“改了提示词之后，已有草稿要不要重写、重写后是否更好”变成可执行、可回看的流程：

- 跨草稿勾选课程，用一个后台任务顺序重写。
- 每课重写前保存旧快照，重写后对比练习/资源/级别/版本变化。
- 每个草稿记录整包质量分前后 delta。
- 当前 prompt 版本 `studio/2`；旧草稿保持 `studio/1`；每课记录实际版本。
- 历史页面可看旧快照与当前内容摘要。

**不做 `tb migrate`。** 等 `tb/2` 真正出现时再做迁移工具。

## 2. 非目标

- `tb/1` → `tb/2` 迁移工具。
- 完整行级 HTML/YAML diff。
- 快照回滚 / 一键恢复。
- 重生成已发布 `content-packs/`（只处理 `drafts/`）。
- 自动判断“新版更好”并自动定稿。
- 取消运行中的进化任务。
- 跨学习者/多用户。

## 3. 决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 批量范围 | 跨草稿选课 | 一次迭代多个包，符合 prompt 调优场景 |
| 对比 | 快照 + 摘要 + 包质量分 | 可回看具体课，成本可控 |
| 版本 | `studio/2` 当前，`studio/1` 旧版 | P3.4 提示词是实质性新版本 |
| 版本粒度 | 每课记录 | 同一草稿可能混有不同版本 |
| 存储 | `drafts/<id>/history/` | 已 gitignore，可人工检查 |
| 执行 | 单后台任务，按草稿分组顺序 | 成本可控、与现有批量互斥 |
| 失败 | 单课失败继续；草稿忙则整组失败 | 隔离与可恢复 |
| 回滚 | 不提供 | 快照仅供人工参考，避免误恢复 |

## 4. Prompt 版本

- `src/testbridge/studio/version.py`：`PROMPT_VERSION = "studio/2"`。
- 新建草稿的 `prompt_version` 使用 `PROMPT_VERSION`。
- 旧草稿没有该字段时按 `studio/1` 处理。
- `generate_lesson` 成功后写：

```json
"steps": {"lessons": {"L-1": {"status": "done", "prompt_version": "studio/2",
  "written_at": "2026-10-26T..."}}}
```

- 旧课程没有 `prompt_version` 时，读取草稿级 `prompt_version`。
- 迁移/升版本不自动重写；由 P3.5 的演进任务显式触发。

## 5. 快照

路径：

```
drafts/<id>/history/<lesson_id>/<timestamp>.json
```

- `timestamp` 为 UTC，格式 `YYYYMMDDTHHMMSSffffffZ`（Windows 文件名安全）。
- 写入用临时文件 + replace；失败也保留旧快照。
- `history/` 已在 `drafts/` 下，被 gitignore。

快照结构：

```json
{
  "schema": "studio-snapshot/1",
  "draft_id": "demo",
  "lesson_id": "L-1",
  "created_at": "2026-10-26T...",
  "prompt_version": "studio/1",
  "module_id": "M01",
  "lesson_title": "单线程执行器",
  "html": "<script ...>...</script><article ...>",
  "exercises": [ ... ],
  "resources": [ ... ],
  "metrics": {
    "exercise_count": 3,
    "types": ["multi_choice", "short_answer", "single_choice"],
    "levels": ["L2", "L2", "L3"],
    "max_level": "L3",
    "resource_count": 1,
    "trust": {"A": 1, "B": 0, "C": 0, "D": 0},
    "html_hash": "sha256..."
  }
}
```

- 课程不存在/未写课时，快照为空内容，指标为 0。
- `html_hash` 用 SHA-256 前 16 位即可；只用于“是否变化”。

## 6. 对比

每课结果：

```json
{
  "lesson_id": "L-1",
  "ok": true,
  "error": null,
  "before": {"prompt_version": "studio/1", "exercise_count": 2, ...},
  "after": {"prompt_version": "studio/2", "exercise_count": 3, ...},
  "changed": {
    "html": true,
    "exercise_count": 1,
    "types_added": ["short_answer"],
    "types_removed": [],
    "max_level_before": "L2",
    "max_level_after": "L3",
    "resource_count": 0,
    "prompt_version": true
  },
  "snapshot_before": "drafts/demo/history/L-1/...json",
  "snapshot_after": "drafts/demo/history/L-1/...json"
}
```

每个草稿结果：

```json
{
  "draft_id": "demo",
  "error": null,
  "quality_before": {"score": 78, "possible": 100, "ok": false},
  "quality_after": {"score": 86, "possible": 100, "ok": false},
  "lessons": [ ... ]
}
```

- 包结构无效时 `quality_*` 为 `null`，但仍尽量快照/重写。
- `ok` 只表示该课重写成功；不代表质量变好。
- 报告写入 `drafts/<id>/history/evolution-<timestamp>.json`。

## 7. 跨草稿任务

### 7.1 状态

`EvolutionJob` 内存状态：

```json
{
  "status": "idle|running|done|failed",
  "total": 3,
  "done": 1,
  "current": {"draft_id": "demo", "lesson_id": "L-1"},
  "results": [ ... ],
  "error": null
}
```

- 进程重启后状态回到 `idle`；历史快照/报告仍在磁盘。

### 7.2 API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/studio/evolution` | 选择页 |
| POST | `/api/studio/evolution` | 启动，body `{"targets":[{"draft_id","lesson_id"}]}` |
| GET | `/api/studio/evolution/status` | 轮询状态 |
| GET | `/studio/<id>/history/<lesson_id>` | 最近一次与当前内容不同的快照 vs 当前 |

- 目标为空、草稿/课程不存在 → 400。
- 进化任务运行中再次启动 → 409 `evolution_running`。
- 未配置模型 → 503 `tutor_disabled`。

### 7.3 执行

1. 目标按草稿分组；组内按大纲顺序。
2. 对每个草稿调用 `JobRunner.run_batch_now(draft_id, fn)` 取得该草稿的批量互斥。
3. `fn` 内：
   - 计算重写前 `quality_draft`（可评估时）；
   - 对每课：`snapshot_lesson(before)` → `generate_lesson(replace=True)` → `snapshot_lesson(after)` → 对比；
   - 单课失败记录后继续；
   - 计算重写后 `quality_draft`；
   - 写报告文件。
4. 草稿忙（已有批量/单课）→ 该草稿整组结果记失败，其它草稿继续。
5. 全部草稿完成 → `done`；任何草稿/课程失败 → `failed`，`error` 记失败数。

### 7.4 并发

- 进化任务运行中，新的进化任务 409。
- 进化任务对某草稿执行时，该草稿的批量/单课任务被现有 `JobRunner` 互斥挡住。
- 同一时间只处理一个草稿；不同草稿按顺序。

## 8. 页面

### 8.1 `/studio/evolution`

- 导航加“演进”。
- 按草稿分组列出模块/课程：
  - 课程状态、当前 prompt 版本；
  - 复选框；
  - 全选/取消（可选）。
- “开始重生成”按钮；未配置模型时禁用。
- 运行中显示 `完成 N/M`、当前草稿/课程。
- 完成后显示：
  - 每个草稿的质量分前后与 delta；
  - 逐课 before/after 摘要、失败原因、历史页链接。

### 8.2 `/studio/<id>/history/<lesson_id>`

- 只读。
- 最近一次与当前内容不同的快照 vs 当前：
  - prompt 版本、课程标题；
  - 练习数/题型/级别、资源数/trust；
  - 旧/新练习题干与资源配置摘要（不渲染完整 HTML）。
- 不提供恢复按钮。

## 9. 错误与边界

| 场景 | 行为 |
|---|---|
| 未配置模型 | 页面提示，动作禁用 |
| 目标为空 | 400 `invalid_request` |
| 草稿/课程不存在 | 400 `invalid_target` |
| 进化任务运行中 | 409 `evolution_running` |
| 目标草稿有运行中任务 | 该草稿失败，其它继续 |
| 单课生成失败 | 记录并继续 |
| 包结构无效 | 质量分 null，仍快照/重写 |
| 快照写入失败 | 该课失败，不重写（避免无快照覆盖） |
| 进程重启 | 任务状态丢失；历史保留 |

## 11. 验收

（实测，2026-10-26）

- [x] 跨两个草稿勾选 3 课，运行后每课有旧/新快照与 delta。
      手工验收：`demo` L-1/L-2 + `other` L-2，`started=3`、`status=done`、`done/total=3/3`；
      每课各 1 份 `snapshot_before` / `snapshot_after`，`prompt_version` 由 `studio/1` 变 `studio/2`。
- [x] 每个草稿显示质量分前后；可下钻历史页。
      `test_evolution_api_rewrites_targets_across_drafts`、`test_history_page_shows_snapshot_and_current`。
- [x] 一课失败不影响其它课/草稿。
      `test_evolution_continues_after_one_lesson_fails`、`test_evolution_does_not_rewrite_when_before_snapshot_fails`。
- [x] 新写课程记录 `studio/2`；旧课程仍显示 `studio/1`。
      `test_evolution_records_prompt_version_and_batch_step`、`test_evolution_page_lists_drafts_and_lessons`。
- [x] 进化任务运行中第二个任务 409；同草稿批量/单课互斥。
      `test_evolution_returns_conflict_while_running`。
- [x] 默认 `pytest` 全绿，`tb validate` 两个包仍 0/0。
      564 passed，3 deselected；`ros2-qos` 与 `sample-sensors` 均 0 error / 0 warning；
      `tb quality content-packs/sample-sensors` 100/100（exit 0）。

## 12. 风险

| 风险 | 取舍 |
|---|---|
| 批量成本高 | 只重写勾选课；不做整包一键 |
| 快照占磁盘 | `history/` 可手工清理；不自动清理 |
| 新版可能更差 | 报告只展示，不自动定稿；快照供人工参考 |
| 长任务无取消 | 逐课状态可恢复；失败继续 |
| 包质量分受其它课影响 | delta 是整包信号，逐课指标单独看 |
| 进程重启丢任务状态 | 历史与报告保留；任务需重跑 |
