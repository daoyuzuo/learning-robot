# P3.4 多模块与批量生成设计（Multi-module & Batch）

- 状态：Implemented，2026-10-26
- 范围：一个内容包含 1–3 个模块、每模块 1–5 课；模块级大纲编辑；包内顺序批量；单课重写替换
- 上游：[P3.1 内容工作台](2026-10-25-p3.1-content-studio-design.md)、[P3.2 质量门禁](2026-10-25-p3.2-quality-gates-design.md)、[P3.3 检索后端](2026-10-25-p3.3-search-backends-design.md)
- 路线图：[ROADMAP](../../ROADMAP.md)

---

## 1. 目标

P3.1–P3.3 能生成单个模块的包。P3.4 把 Studio 提升到“课程包”级别：

- 一个包内支持 **1–3 个模块**，每模块 **1–5 课**。
- 概念保持全局表；模块声明自己负责的概念子集，课程声明本课概念。
- 大纲 HTML 可编辑模块标题、概念列表与课程归属；保存时重写 `module.yaml`。
- 包内顺序批量：调研/写课只跑 `pending` / `failed`，逐课更新状态。
- 单课“重写”替换旧练习/资源，不产生重复 ID。
- 旧草稿（单模块、扁平 outline、无新字段）继续可用。

## 2. 非目标

- 跨主题批量建包（多个独立内容包）。
- 并行批量 / 并发限流。
- 取消正在运行的批量任务。
- 自动发布、多人协作、草稿版本历史。
- 修改 `tb/1` 内容契约（多模块本就是合法结构）。
- 自动删除被移出大纲的旧模块/课程文件。

## 3. 决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 批量范围 | 包内多模块 + 批量 | 直接服务“一次做完一个课程包” |
| 执行方式 | 顺序，只跑 pending/failed | 成本可控、失败隔离、可恢复 |
| 重跑 | 单课“重写”替换旧输出 | 批量安全，单课可迭代 |
| 输入 | 表单定模块数/每模块课数 | 确定性强，便于校验 |
| 概念 | 全局概念 + 模块子集 + 课概念 | 与 `tb/1` 一致，避免重复定义 |
| 大纲编辑 | 模块结构可编辑 | 保持 P3.1 的 contenteditable 体验 |
| 旧草稿 | 回退为单模块 M01 | 不破坏已有 drafts |
| 并发 | 批量与单课互斥 | 避免同一草稿状态互相覆盖 |

## 4. 数据模型

### 4.1 草稿字段

`draft.json` 新增：

```json
{
  "module_count": 2,
  "lessons_per_module": 2,
  "lesson_count": 4
}
```

- `module_count`：1–3。
- `lessons_per_module`：1–5。
- `lesson_count = module_count * lessons_per_module`，保留给旧代码/兼容。
- 旧草稿缺 `module_count` / `lessons_per_module` 时：
  `module_count=1`，`lessons_per_module=lesson_count`（缺 `lesson_count` 则 1）。
- `DraftStore.create` 接受新字段；旧调用只传 `lesson_count` 时按单模块处理。

### 4.2 计划对象

```python
@dataclass(frozen=True)
class LessonPlan:
    lesson_id: str
    title: str
    minutes: int
    objectives: list[str]
    queries: list[str]
    module_id: str = "M01"
    concepts: list[str] = field(default_factory=list)

@dataclass(frozen=True)
class ModulePlan:
    module_id: str
    title: str
    concepts: list[str] | None
    lessons: list[LessonPlan]
```

- `ModulePlan.concepts` 为 `None` 表示旧 HTML 没有模块概念信息；保存时跳过 `module.yaml` 重写。
- `LessonPlan` 新字段在末尾，旧位置参数构造保持可用。

### 4.3 大纲 JSON

新形态：

```json
{
  "pack_title": "ROS 2 执行器与回调组",
  "concepts": [
    {"id": "executor-basics", "title": "执行器基础", "domain": "ros2",
     "target_level": "L2", "prerequisites": [], "weight": 1.0,
     "evidence_criteria": []}
  ],
  "modules": [
    {"id": "M01", "title": "执行器基础", "concepts": ["executor-basics"],
     "lessons": [
       {"id": "L-EXEC-001", "title": "单线程执行器", "minutes": 20,
        "concepts": ["executor-basics"], "objectives": ["..."],
        "exercise_intents": ["..."], "research_queries": ["..."]}
     ]}
  ]
}
```

- 旧扁平形态 `module_title` + `lessons` 仍接受，自动包装为 `M01`。
- 概念总数 1–12；每课至少 1 个概念；每课概念必须属于所属模块；每个模块概念至少出现在一课。
- 模块 ID/课程 ID 全局唯一，匹配 `^[A-Za-z][A-Za-z0-9-]*$`。
- `modules` 数量必须等于 `module_count`；每个模块课程数必须等于 `lessons_per_module`。
- 模块概念必须存在于全局 `concepts`。

## 5. 大纲流水线

### 5.1 生成

`OUTLINE_SYSTEM` 输出 `pack_title` + `concepts` + `modules`。每模块概念 1–4 个，每课概念 1–2 个；课程数由服务端给定。旧格式提示词不再使用。

`generate_outline` 使用草稿的 `module_count` / `lessons_per_module` 解析与校验。

### 5.2 写盘

`write_outline(store, draft_id, parsed) -> list[ModulePlan]`：

- `pack.yaml`：`title = parsed.pack_title`（旧格式用 `module_title`）。
- `concepts.yaml`：全局概念。
- 每个 `modules/<module_id>/module.yaml`：
  ```yaml
  schema: tb/1
  id: M01
  title: ...
  priority: P1
  concepts: [...]
  lessons: [...]
  order: 1
  ```
- `outline.html`：模块 section 包住课 section。
- 重算 `steps.research` / `steps.lessons` 的键为全部课程 ID；`steps.batch` 置 `pending`。

### 5.3 HTML 结构

```html
<article class="tb-outline">
  <h1 class="tb-pack-title">包标题</h1>
  <section class="tb-outline-module" id="M01">
    <h2 class="tb-module-title">模块标题</h2>
    <ul class="tb-module-concepts"><li>executor-basics</li></ul>
    <section class="tb-outline-lesson" id="L-EXEC-001">
      <h3 class="tb-lesson-title">单线程执行器</h3>
      <p class="tb-minutes">20</p>
      <ul class="tb-lesson-concepts"><li>executor-basics</li></ul>
      <ul class="tb-objectives">...</ul>
      <ul class="tb-queries">...</ul>
    </section>
  </section>
</article>
```

- 只有列表里的概念 ID 是权威；标题可编辑。
- `render_outline_html(pack_title, modules)` 负责转义与结构。
- `parse_outline_html(html) -> list[ModulePlan]`：
  - 有 `tb-outline-module` → 读模块结构。
  - 没有 → 旧扁平 HTML，回退为单个 `M01`，`concepts=None`，课标题兼容旧 `h2`。
  - 无课程 → `OutlineError`。

### 5.4 保存编辑

`PUT /api/studio/<id>/outline`：

1. `sanitize_fragment`。
2. `parse_outline_html`。
3. 校验模块概念都存在（跳过 `concepts=None`）；对每个有概念信息的模块，还要求
   每课概念属于所属模块、每个模块概念至少被一课覆盖；不满足返回 400。
4. 写 `outline.html`。
5. `write_module_files` 重写有概念信息的 `module.yaml`；`concepts=None` 的模块
   保留原 concepts，只更新 title / lessons / order（没有原文件时新建）。
6. 解析结果里已不存在的模块：把它的 `module.yaml` 改名为
   `module.yaml.removed`（validator 只 glob `*/module.yaml`），lesson 文件保留为孤儿。
7. 按扁平课程重算 `steps.research` / `steps.lessons`；`steps.batch` 置 `pending`；
   同步 `draft.module_count` / `draft.lesson_count` 为实际模块数/课程数，
   `lessons_per_module` 仍作为创建与生成目标。
8. 返回 `{"lessons": [...], "modules": [...]}`。

手动编辑大纲后，实际模块数 / 课程数可以与创建时不同；保存以实际结构为准，
页面按实际结构显示模块数与课程数。

被删课程、被移出模块的 lesson 文件保留在磁盘，不删除。已写课被移动模块时，
`steps.lessons` 置 `failed`（`课程已移动到新模块，需要重写`），批量/重写会以
`replace=True` 写新模块并清理旧练习/资源 ID。

## 6. 写课与重写

- `write_lesson` 使用 `lesson.module_id` 定位 `modules/<id>/module.yaml` 与 lesson 文件；不再有固定 `MODULE_ID`。
- manifest：
  - `module = lesson.module_id`。
  - `concepts = lesson.concepts`（非空时）；否则沿用“练习概念 union → 模块概念”的回退。
- `write_lesson(..., replace=False)`：
  - `replace=True` 且旧 lesson 文件存在时，读旧 manifest，从 `exercises.yaml` / `resources.yaml` 删除该课旧 ID；
  - 删除后仍检查与其它课 ID 冲突；
  - 写入新练习/资源/HTML；
  - 旧文件在旧模块（课程被移动模块）时保留，不主动删除。
- 单课重写：`POST /api/studio/<id>/lessons` body `{"lesson_id": "...", "replace": true}`。
- 批量写课：`failed` 课使用 `replace=True`，`pending` 课使用 `replace=False`。

## 7. 批量执行

### 7.1 状态

`draft.json.steps.batch`：

```json
{"status": "pending|running|done|failed", "mode": "research|lessons",
 "done": 0, "total": 0, "error": null, "at": null}
```

### 7.2 目标选择

- `mode=research`：`steps.research[lesson].status ∈ {pending, failed}`。
- `mode=lessons`：`steps.lessons[lesson].status ∈ {pending, failed}`。
- 目标按模块顺序、模块内顺序排列。
- 无目标：不启动任务，返回 `{"started": []}`。

### 7.3 执行

`POST /api/studio/<id>/batch` body `{"mode": "research"|"lessons"}`：

- `JobRunner.start_batch` 启动一个批任务；批量任务内部顺序调用现有 research/lesson 业务函数。
- 每课开始前 `steps.<mode>[lesson].status = running`，结束后 `done` / `failed`。
- 每完成一课更新 `steps.batch.done`。
- 单课失败记录错误后继续下一课。
- 全部成功 → `batch.status = done`；有失败 → `batch.status = failed`，`error = "<N> 课失败"`。
- 批任务不并行；同一草稿的批量与单课任务互斥。

### 7.4 并发

`JobRunner`：

- `start`（单课）遇到该草稿正在批量 → `JobBusy`。
- `start_batch` 遇到该草稿任何单课正在运行 → `JobBusy`。
- 不同草稿互不影响。

### 7.5 UI

- 第 2 步“调研”：`全部调研` 按钮；显示 `完成 N/M`；每课保留单课按钮。
- 第 3 步“写课”：`全部写课` 按钮；done 课显示 `重写这一课`；每课显示当前 backend。
- 课程按模块分组显示。
- 轮询刷新 batch 状态与逐课状态。

## 8. 兼容与错误

| 场景 | 行为 |
|---|---|
| 旧草稿缺 module 字段 | 单模块，`lessons_per_module=lesson_count` |
| 旧扁平 outline.html | 回退 M01，`concepts=None`；保存时保留原 concepts，只更新 title/lessons/order |
| 旧 lesson 无 concepts | manifest 回退现有 union 逻辑 |
| 模块概念不存在 | 保存大纲 400 `invalid_outline` |
| 课程概念不属于模块 / 模块概念未被覆盖 | 保存大纲 400 `invalid_outline` |
| 模块/课数不符 | 生成大纲失败，job 记错误 |
| 批量目标为空 | 不启动任务；批量仍为 running 时 409 `step_running` |
| 批量中单课失败 | 继续，最终 batch failed |
| 批量与单课并发 | 409 `step_running` |
| 重写时旧 ID 被其它课使用 | 拒绝，`LessonError` |
| 已写课被移动模块 | 步骤置 failed；批量/重写以 `replace=True` 写新模块，旧文件保留 |
| 手动编辑改变模块/课数 | 保存更新 `module_count` / `lesson_count`，`lessons_per_module` 为生成目标，页面显示实际数 |
| 模块被移出大纲 | `module.yaml` 改名为 `module.yaml.removed`，lesson 文件保留 |

## 9. 质量门禁

- 质量规则不改；多模块包按全部模块概念计算覆盖。
- `exercise_concept_outside_lesson` 现在会检查练习概念是否属于该课计划概念；生成提示词会把课概念放进 outline HTML。
- 批量写课后仍需在 Studio 校验/定稿；批量不自动定稿。

## 12. 风险

| 风险 | 取舍 |
|---|---|
| 多模块大纲模型输出不稳 | 结构化校验 + 人工编辑；失败可重生成 |
| 批量成本高 | 只跑待办；逐课按钮；不自动定稿 |
| 替换误删其它课 ID | 只删旧 lesson manifest 列出的 ID；冲突仍拒绝 |
| 旧草稿兼容 | 单模块回退；保存不破坏旧 module.yaml |
| 模块移动留下孤儿文件 | 不自动删除；validator 只读 module.yaml 引用 |
| 批量长任务无取消 | 逐课状态可恢复；失败继续 |
