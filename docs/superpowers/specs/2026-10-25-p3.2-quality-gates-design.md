# P3.2 质量门禁设计（Quality Gates）

- 状态：Implemented，2026-10-25
- 范围：对单个内容包做确定性的质量评估，Studio 定稿前阻断硬错误，并给出 0–100 质量分
- 上游：[P1 教学引擎设计](2026-10-24-teaching-engine-design.md)、[P3.1 内容工作台](2026-10-25-p3.1-content-studio-design.md)
- 路线图：[ROADMAP](../../ROADMAP.md)

---

## 1. 目标

P3.1 解决了“能不能生成”，P3.2 解决“生成得够不够好”。

- 用确定性规则检查引用、可信度、练习覆盖、目标级别、结构与调研充分性。
- 硬错误阻断 Studio 定稿；警告只展示与扣分。
- 给出可解释的 0–100 质量分，分项可下钻到具体课程、概念、资源。
- 同一套规则既服务草稿（带调研档案），也服务已发布包（结构类检查）。

**不做 LLM 评判。** 质量门禁是确定性核心的一部分，不调用模型。

## 2. 非目标

- 不自动改写或修复内容。
- 不用总分阈值阻断发布。
- 不把质量报告写入 `content-packs/`。
- 不修改现有内容包，也不因新规则回溯阻断它们的使用。
- 不做批量生成、多模块、`tb migrate`（P3.3–P3.5）。
- 不改变 `tb validate` 的契约校验语义。

## 3. 决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 门禁硬度 | 硬规则阻断 + 质量分展示 | 规则可解释，不靠拍脑袋阈值 |
| 维度 | 引用可信度 / 练习覆盖 / 目标级别 / 结构与调研 | 覆盖 ROADMAP 的 P3 质量项 |
| 运行位置 | Studio 完整报告 + `tb quality` CLI 结构报告 | 草稿有调研档案；已发布包没有 |
| 代码位置 | 新增 `src/testbridge/quality/` | 纯函数、CLI 与 Studio 共用，不污染契约校验器 |
| 溯源缺失 | 不评估、不计分、明确标注 | CLI 不可能凭空拿到草稿调研 |
| 绕过 | 不提供 `force` / `skip_quality` | 门禁一旦可绕过就失去意义 |

## 4. 术语与定义

### 4.1 级别顺序

`L1 < L2 < L3 < L4`，对应 `{"L1": 1, "L2": 2, "L3": 3, "L4": 4}`。

### 4.2 URL 归一化

溯源比较使用归一化 URL：

1. 去首尾空白；只接受 `http` / `https`。
2. scheme、hostname 转小写；去掉 userinfo。
3. 去掉默认端口（http 80、https 443）。
4. path 去掉末尾 `/`；空 path 记为 `/`。
5. **忽略 query 与 fragment。**

理由：调研命中常带追踪参数或锚点，资源链接往往不带；按 scheme + host + path 比较能稳定命中。代价是同 path 不同 query 的页面会被视为同一来源，对文档型内容可接受。

### 4.3 调研档案

Studio 草稿的 `research/<lesson-id>.json`，结构见 P3.1 §7：

```json
{"lesson_id": "L-1", "queries": ["..."], "searches": 1, "errors": [],
 "hits": [{"url": "...", "trust": "A", "authority": 3, ...}]}
```

- 一个资源“可追溯”指：它的归一化 URL 出现在**任意一课**的档案 `hits[].url` 中。
- 一个命中是 A/B 级：`trust` 为 `A` 或 `B`；若没有 `trust` 字段，则 `authority >= 2` 视为 A/B。
- 档案文件名 stem 即课程 id。
- “实际查询数”取档案的 `len(queries)`；字段缺失或不是数组时记为 0。
- 档案无法读取、不是 JSON 对象、或 `hits` 不是数组时，记为 malformed。

### 4.4 结构有效

质量评估要求内容包先通过 `validate_pack`。结构无效时不做质量评估，避免在坏数据上产生误导分数。

## 5. 规则

### 5.1 硬错误（阻断定稿）

| 代码 | 条件 | 适用 |
|---|---|---|
| `quality.resource_unsourced` | 某资源的归一化 URL 不在任何调研档案命中里 | Studio |
| `quality.resource_trust` | 某资源 `trust` 不是 `A` / `B` | 两者 |
| `quality.concept_without_exercise` | 模块概念没有任何练习覆盖 | 两者 |
| `quality.lesson_too_few_exercises` | 某课练习数 < 2 | 两者 |
| `quality.exercise_concept_outside_lesson` | 某课练习引用的概念不在该课 manifest 的 `concepts` 中 | 两者 |
| `quality.lesson_level_short` | 某课 manifest 列出的练习中最高级别 < 该课 `target_level` | 两者 |
| `quality.concept_level_short` | 全包内覆盖该概念的练习最高级别 < 该概念 `target_level` | 两者 |
| `quality.research_missing` | 某课没有调研档案 | Studio |
| `quality.research_empty` | 某课调研档案 `hits` 为空 | Studio |
| `quality.research_malformed` | 调研档案不是合法 JSON 或结构不符 | Studio |

说明：

- 概念没有任何练习时只报 `concept_without_exercise`，不重复报 `concept_level_short`。
- 课程没有练习时只报 `lesson_too_few_exercises`，不重复报 `lesson_level_short`。
- 练习引用了包内不存在的概念属于契约错误，由 `tb validate` 负责，质量层跳过该引用。
- 内容包结构无效时 `evaluate_pack` 抛 `QualityUnavailable`，不返回报告；调用方按“无法评估”处理（Studio 返回 `quality: null`，CLI 退出码 2）。

### 5.2 警告（展示与扣分，不阻断）

| 代码 | 条件 |
|---|---|
| `quality.resource_metadata` | 资源缺 `license` / `last_verified` / `why` 任一 |
| `quality.lesson_no_resource` | 某课 manifest 的 `resources` 为空 |
| `quality.type_variety_low` | 全包练习题型少于 3 种 |
| `quality.research_queries_low` | 某课档案实际查询数 < `ceil(预算 / 2)` |
| `quality.lesson_no_ab_source` | 某课档案没有任何 A/B 级命中 |

## 6. 质量分

总分 100；每一项按比例给分，四舍五入（`floor(x + 0.5)`）。

| key | 指标 | 分值 | 计算 |
|---|---|---|---|
| `provenance.traceable` | 资源可追溯 | 15 | 可追溯资源数 / 资源总数 |
| `provenance.trust` | 资源可信 | 10 | A/B 资源数 / 资源总数 |
| `provenance.metadata` | 资源元数据完整 | 5 | license、last_verified、why 齐全的资源数 / 资源总数 |
| `coverage.concepts` | 概念有练习 | 15 | 有练习的概念数 / 概念总数 |
| `coverage.lesson_exercises` | 每课至少 2 题 | 10 | 满足的课程数 / 课程总数 |
| `coverage.type_variety` | 题型多样 | 5 | `min(题型种数, 3) / 3` |
| `level.lessons` | 课级达标 | 10 | 最高题级 ≥ 课目标的课程数 / 课程总数 |
| `level.concepts` | 概念级达标 | 10 | 最高题级 ≥ 概念目标的概念数 / 概念总数 |
| `research.dossiers` | 调研可用 | 5 | 有档案且至少 1 条命中的课程数 / 课程总数 |
| `research.queries` | 调研充分 | 5 | 查询数 ≥ `ceil(预算 / 2)` 的课程数 / 课程总数 |
| `structure.objectives` | 目标与时长完整 | 5 | objectives 非空且 minutes > 0 的课程数 / 课程总数 |
| `structure.lesson_resources` | 每课有资源 | 5 | 有资源的课程数 / 课程总数 |

规则：

- 分母为 0 时该项得 0 分。
- 只计算**可评估项**的 `possible` 之和；最终分数 `score = round(100 × earned / possible)`，`possible` 为 0 时分数为 0。
- 有调研档案且给定额度时满分 100；无档案时只计算 `coverage.*`（30）+ `level.*`（20）+ `structure.*`（10），共 60；有档案但没给预算时跳过 `research.queries`（5），共 95。
- 分数**不阻断**；硬错误才阻断。
- 报告同时保留原始 `earned` / `possible`，避免归一分掩盖信息。

## 7. 模块边界

```
src/testbridge/quality/
  __init__.py
  report.py       # QualityIssue / QualityMetric / QualityReport / 打分与归一
  structural.py   # 覆盖、级别、结构规则
  provenance.py   # URL 归一化、档案加载、溯源与调研规则
  evaluate.py     # evaluate_pack(...) / evaluate_draft(...)
```

依赖方向：

- `quality/` 可以 import `testbridge.content.repository` 与 `testbridge.contract`。
- `quality/` **不得** import `studio`、`learning`、`mastery`、`schedule`、`evidence`。
- `studio/`、`web/studio.py`、`cli` 可以 import `quality/`。

公开接口：

```python
def evaluate_pack(
    pack_dir: Path,
    *,
    research_dir: Path | None = None,
    budget: int | None = None,
) -> QualityReport: ...

def evaluate_draft(
    pack_dir: Path,
    *,
    research_dir: Path,
    budget: int,
) -> QualityReport: ...
```

`evaluate_draft` 等价于带调研的 `evaluate_pack`，保留独立命名让 Studio 调用意图清晰。

`evaluate_pack` 在内容包结构无效时抛 `QualityUnavailable`（携带 `ValidationReport`），由调用方决定如何展示。

## 8. 数据模型

```python
@dataclass(frozen=True)
class QualityIssue:
    code: str
    message: str
    severity: Literal["error", "warning"]
    lesson_id: str | None = None
    concept_id: str | None = None
    resource_id: str | None = None

@dataclass(frozen=True)
class QualityMetric:
    key: str
    label: str
    earned: int
    possible: int
    detail: str          # 例："3/4 课达标"

@dataclass(frozen=True)
class QualityReport:
    score: int                      # 0–100（可能归一）
    metrics: list[QualityMetric]
    errors: list[QualityIssue]
    warnings: list[QualityIssue]
    provenance_evaluated: bool
    research_evaluated: bool
    earned: int
    possible: int

    @property
    def ok(self) -> bool: ...

    def as_dict(self) -> dict: ...
```

`as_dict()` 形状：

```json
{
  "score": 82,
  "earned": 82,
  "possible": 100,
  "ok": false,
  "provenance_evaluated": true,
  "research_evaluated": true,
  "metrics": [{"key": "...", "label": "...", "earned": 15, "possible": 15, "detail": "..."}],
  "errors": [{"code": "...", "message": "...", "severity": "error", "lesson_id": null, "concept_id": null, "resource_id": null}],
  "warnings": [...]
}
```

## 9. Studio 集成

### 9.1 适配器

`studio/gates.py` 增加：

```python
def quality_draft(store: DraftStore, draft_id: str) -> QualityReport:
    draft = store.load(draft_id)
    return evaluate_draft(
        store.path(draft_id),
        research_dir=store.path(draft_id) / "research",
        budget=int(draft["searches_per_lesson"]),
    )
```

### 9.2 校验接口

`POST /api/studio/<id>/validate`：

1. 跑 `validate_draft`。
2. 结构有错：返回 `quality: null`、`quality_skipped: "invalid_pack"`，不跑质量评估。
3. 结构无错：跑 `quality_draft`；若抛 `QualityUnavailable`，返回 `quality: null`、`quality_skipped: "unavailable"` 并附一条 warning。
4. 合并结果：
   - `errors` = 结构错误 + 质量硬错误（格式 `code: message`）。
   - `warnings` = 结构警告 + 质量警告。
   - `ok` = 无任何错误。
5. 写入 `draft.json`：

```json
"validation": {
  "status": "done|failed", "error": null, "at": "...",
  "issues": ["..."],
  "quality": { "...QualityReport.as_dict()..." }
}
```

响应：

```json
{"ok": true, "errors": [], "warnings": [], "quality": {...}, "quality_skipped": null}
```

### 9.3 定稿门禁

`studio/gates.py::promote` 在结构校验之后、资源可达性之前跑质量门禁：

- 结构错误 → `PromoteError("invalid_pack", ...)`（现状）。
- 质量硬错误 → `PromoteError("quality_gate", first_5_messages)`。
- 质量警告不阻断。
- `force=True` 只允许覆盖已有目录，**不跳过质量门禁**。
- `skip_verify=True` 只跳过资源 URL 的 HTTP 可达性，**不跳过质量门禁**。

`/api/studio/<id>/promote` 返回 400 / `quality_gate`。

### 9.4 页面

`/studio/<id>` 第 4 步增加：

```
质量分 82/100    [硬错误 0 · 警告 3]
分项：可追溯 15/15 · 可信 10/10 · ...
问题：
ERROR quality.lesson_level_short: ...
WARN quality.resource_metadata: ...
```

- 服务端渲染上次报告；客户端 `studio.js` 在校验后更新。
- 只使用 `textContent` 写入，不拼 `innerHTML`。
- 溯源未评估时显示“溯源与调研未评估”。

## 10. CLI

新增：

```bash
tb quality <pack> [--research-dir DIR] [--budget N] [--json]
```

行为：

- 如果 `<pack>/draft.json` 存在：
  - 未显式给 `--research-dir` 时用 `<pack>/research`；
  - 未显式给 `--budget` 时用 `draft.json.searches_per_lesson`。
- 如果最终没有预算：跳过 `research.queries` 指标与 `research_queries_low` 警告，分数按剩余项归一。
- 结构无效：打印 `tb validate` 会给出的错误，再打印 `run tb validate first`，退出码 2。
- 显式指定的 `--research-dir` 不存在：打印 `ERROR research_dir: not found: ...`，退出码 2。
- `--budget` 小于 1（包括从 `draft.json` 解析出的非正数）：打印 `ERROR budget: must be >= 1: ...`，退出码 2。
- 有硬错误：退出码 1；只有警告：退出码 0。
- `--json` 输出 `QualityReport.as_dict()`。
- 文本输出：

```
quality: 82/100
ERROR quality.lesson_level_short: ...
WARN quality.resource_metadata: ...
provenance: evaluated
research: evaluated
```

- 对 `content-packs/` 下的包，默认没有档案，输出 `provenance: not evaluated` / `research: not evaluated`，分数为结构分归一。

## 11. 提示词调整

`LESSON_SYSTEM` 增加：

1. 每课至少 2 道练习。
2. 每道练习的 `level` 不低于它覆盖的所有概念中的最高 `target_level`。
3. 每课至少 1 道练习达到课程 `target_level`。
4. 每个概念至少被 1 道练习覆盖。
5. 每课至少 1 条 A/B 资源，且 `license` / `last_verified` / `why` 完整。

不修改 `OUTLINE_SYSTEM` 的结构要求。

## 15. 风险

| 风险 | 取舍 |
|---|---|
| 规则过严导致生成的包频繁被阻断 | 级别规则直接推动提示词改进；如真实数据证明过严，后续调整阈值并升 spec 版本 |
| 现有包出现大量问题 | 只报告不阻断；不回溯修改 |
| URL 归一化误判 | 只比较 scheme/host/path；记录取舍；后续可加白名单 |
| 分数看起来精确但权重主观 | 分数不阻断；规则才是门禁；分项透明可下钻 |
| CLI 与 Studio 结果不一致 | 共用 `evaluate_pack`；Studio 仅多传档案与预算 |
