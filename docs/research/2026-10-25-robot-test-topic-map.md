# 机器人整机/系统测试 + HIL/SIL 测试开发：主题地图

> 用途：仅提供主题与子主题，供另一套课程化框架使用。  
> 不含：课程信息、学时、周计划、考核方式、学习成果等课程化字段。  
> 标记：**核心** = 目标岗位直接需要；**扩展** = 面试/岗位加分；**可选** = 按方向选学。

## 1. 测试与质量体系

### 1.1 测试策略与风险
- 测试策略的输入：需求、风险、架构、变更、现场场景
- 风险分级：安全/功能/体验/成本/合规
- 测试分层：单元 → 集成 → 系统 → 验收
- 测试左移/右移
- 版本准入/准出
- **核心**

### 1.2 测试设计方法
- 等价类、边界值、判定表、状态迁移、场景法、组合/配对测试
- 任务链测试：感知 → 决策 → 规划 → 控制 → 执行
- 长尾场景、动态障碍、传感器失效、通信降级
- 故障注入作为测试设计方法
- **核心**

### 1.3 测试预言与量化指标
- Oracle 类型：规格、参考模型、蜕变、一致性、统计
- 指标：成功率、终点误差、路径长度、耗时、碰撞率、恢复成功率、延迟、抖动、漂移
- 单次阈值 vs N 次统计
- 均值 vs P95/P99 vs worst-case
- **核心**

### 1.4 缺陷管理与根因分析
- 缺陷分类：需求/设计/实现/集成/环境/传感器/标定/时序/通信/安全
- 5Why、鱼骨图、8D、FTA
- 逃逸分析：为什么没测出来
- 缺陷复现与证据链
- **核心**

### 1.5 覆盖率与版本准入
- 需求覆盖、代码覆盖、场景覆盖、风险覆盖、接口覆盖
- 回归策略、blocker/critical、已知问题、回滚方案
- 机器人特有：场景库覆盖、故障模式覆盖、sim-to-real 覆盖
- **核心**

### 1.6 实验设计与统计
- 重复次数、样本量、置信区间
- 变异来源：环境、负载、温度、传感器噪声、操作者
- Flakiness、回归基线、趋势分析
- 可视化：箱线图、P95/P99、漂移曲线、热力图
- **核心**

### 1.7 标准与合规地图
- 通用：ISO/IEC/IEEE 29119、ISTQB 术语
- 汽车：ASPICE、ISO 26262、ISO 21434、ISO 14229、ISO 11898
- 机器人：ISO 10218-1/-2、ISO/TS 15066、ISO 3691-4、ISO 13482、ISO 12100、ISO 13849-1、IEC 62061/IEC 61508
- 关键区别：汽车 ASIL vs 机器人 PL/SIL
- **扩展**

### 1.8 机器人测试评价与认证
- 性能评价、可靠性、EMC、安全、智能化评价
- 认证/市场准入：CE、UL、CQC 等
- 机器人测试评价体系与指标
- **扩展**

## 3. 自动化测试与测试框架

### 3.1 框架分层
- 用例层、夹具/环境层、适配层、激励层、断言/预言层、证据层、调度层、集成层
- 数据与代码分离、配置管理、环境复位
- **核心**

### 3.2 设计模式与可维护性
- Adapter、Factory/Builder、Data-driven、Keyword-driven、Plugin
- 反模式：硬编码、隐式等待、全局状态、无清理、断言缺失
- **核心**

### 3.3 AI 辅助框架的“去黑盒化”
- 逐文件回读、依赖分析、数据流
- 识别 AI 生成风险：不存在的 API、过度抽象、复制粘贴、异常处理缺失、硬编码路径
- 自己重写核心模块、框架单测、设计决策记录
- **核心**

### 3.4 机器人适配层
- `DutAdapter` 接口设计
- CAN mock、ROS2 mock/最小实现
- 发布/订阅、服务调用、bag 读取
- 学习实验与生产项目的边界
- **核心**

### 3.5 测试数据与证据管理
- 用例数据、日志、bag、截图、波形、报告的统一命名与归档
- 失败现场保留、数据脱敏、体积管理
- **核心**

### 3.6 测试报告与看板
- 通过/失败/跳过/阻塞
- 指标趋势、失败分类、Top 缺陷、版本对比
- HTML/Markdown 报告
- **核心**

### 3.7 CI/CD
- 流水线：lint → unit → integration → HIL smoke → regression → report
- Jenkins/GitLab CI/GitHub Actions
- pytest 集成、制品归档、失败通知、并行/缓存
- HIL 资源锁、夜间回归、flaky test 隔离
- **扩展**

## 8. 故障注入与安全

### 8.1 故障模型
- 传感器：卡死、漂移、噪声、断线、时间戳异常
- 执行器：卡死、限幅、过温
- 通信：丢包、延迟、乱序、错误帧
- 电源：跌落、断电
- 环境：温度、振动
- **核心**

### 8.2 注入方式
- 硬件 FIU
- 总线注入：CAN/Ethernet
- 软件注入
- 环境注入
- **核心**

### 8.3 安全验证
- 安全状态、降级、告警、恢复
- 诊断覆盖率、故障反应时间

### 8.4 FMEA/FTA 与故障传播
- 故障树、失效模式、影响分析
- 跨层故障传播链
- **核心**

### 8.5 标准与区别
- 汽车：ISO 26262/ASIL
- 机器人：ISO 10218、ISO/TS 15066、ISO 3691-4、ISO 13482
- 机械安全：ISO 13849-1（PL）、IEC 62061/IEC 61508（SIL）

- **扩展**

### 8.6 证据链
- 注入时间、预期、实际、恢复

## 附：主题取舍说明

### 保留并强化的主题
- 测试方法与度量：你是测试出身，但机器人需要 oracle、统计、指标，不能只停在“用例执行”。
- 测试框架：你已有 AI 辅助框架，主题应落在“架构复盘、适配层、CI 集成”，不是“再搭一个”。
- CAN/FuSa：你的存量优势，主题应落在“迁移到 CANopen/EtherCAT/机器人安全”。
- Linux/日志/网络：所有机器人测试岗的通用底座。

### 新增的主题
- 机器人系统通识（硬件/软件/通信/安全/实时性）
- ROS2/DDS/QoS/TF
- HIL/SIL 架构、plant model、I/O、时间同步
- Ethernet/EtherCAT
- 统计与实验设计
- 项目迁移与案例表达

### 降级/不建议投入的主题
- 从零学 C++/控制器开发
- 深挖 SLAM/RL/VLA 数学
- 全总线（LIN/FlexRay/MOST/CC-Link）
- Kubernetes/云原生
- 从零再搭一个测试框架
- 虚构机器人项目
