001

测试预言与量化指标

学完你能：为 SLAM 定义指标、阈值、样本量、分位数和失败判定。

开课前 3 分钟：先回忆

  1. 任务链五个节点是什么？
  2. 故障注入实验必须记录哪些字段？
参考答案

感知、决策、规划、控制、执行；注入实验要记录假设、注入点、方式、观测、预期降级和恢复判据。

本课主读：R-29119-4《ISO/IEC/IEEE 29119-4:2021 测试技术》。重点看测试条件、预言和覆盖的组织方式。

某团队做了一次“成功”的机器人测试：10 次抓取全部完成，测试报告写“通过”。上线后客户反馈，抓取成功率只有 90%，而且失败集中在轻质光滑箱子上。团队回头检查，发现测试只用了一种箱子，判定标准是“机器人没有报错”，既没有统计成功率，也没有定义什么算“抓取成功”。

这就是测试预言（oracle）缺失：系统跑了，但没有人定义“结果对不对”。机器人行为往往没有唯一正确答案，因此预言的选择比用例本身更关键。本课讲清楚五类预言、常用指标、以及如何把指标写成可执行的判定规则。

一、五类测试预言

预言类型什么时候用机器人例子风险
规格比对需求给出明确阈值或输出急停距离不超过 0.5 m；充电对接成功率不低于 99%规格本身错误或过时
参考模型有可信的仿真、解析模型或旧版本运动学逆解与规划器输出对比；新旧版本行为对比参考模型也有缺陷
蜕变关系无完整参考模型，但输入变换与输出变化有关系障碍物移远后最小安全距离不应变小；地图放大后路径长度应增加关系太弱，发现不了细微错误
一致性检查多传感器或多实现应相互印证视觉与激光对同一障碍的位置一致；两台机器人对同一地图的定位一致共同失效导致一致但错误
统计判定结果有随机性，需要多次运行100 次抓取的成功率与置信区间；P95 延迟样本不足，结论不可靠

选择预言时先问：有没有可信的期望值？如果没有，能不能找到输入输出之间的关系？如果关系也没有，能不能用统计分布或一致性来判定？最忌讳的是“没有报错就算通过”。

二、常用指标

  • 成功率：任务完成次数 / 总次数。要定义“完成”的判定，例如抓取后保持 3 s 不掉落。
  • 终点误差：实际终点与目标点的距离。要说明是单次最大、均值还是 P95。
  • 路径长度 / 耗时：效率指标。要和基准路径或时间预算比较。
  • 碰撞率：单位时间或单位距离的碰撞次数。安全关键指标，通常要求零容忍。
  • 恢复成功率：故障后恢复的次数 / 故障次数。比“有没有故障”更能反映系统韧性。
  • 延迟与抖动：感知到执行的端到端时间；抖动反映稳定性。
  • 漂移：长时间运行后位姿、时间戳或传感器读数的累积偏差。

指标本身不是判定。一个“成功率 95%”如果没有定义样本量、置信区间和失败条件，就无法判断是否达标。

三、单次阈值 vs N 次统计

单次阈值适合硬约束：单次碰撞即失败、急停距离超过 0.5 m 即失败、单次越界即失败。这类指标不取平均，因为一次严重失效就足以否定系统。

N 次统计适合有随机性的任务：抓取成功率、导航成功率、恢复时间分布。需要定义重复次数、样本量、置信区间和失败判定。例如“抓取成功率不低于 98%，95% 置信区间下限不低于 96%”，比“跑了 100 次成功 98 次”更严谨。

指标推荐口径理由
急停距离单次最大值 + 全部样本安全硬约束，不能被平均掩盖
抓取成功率N 次比例 + 置信区间有随机性，需要统计判断
端到端延迟P95 / P99 + worst-case尾部延迟影响体验和安全
路径长度均值 + 标准差对称、无长尾时均值有意义
恢复时间P95 + 最大恢复时间少数长时间卡死最危险

四、均值、分位数与 worst-case

均值回答“平均怎么样”，分位数回答“最差的 5% 有多差”，worst-case 回答“最坏能坏到什么程度”。机器人指标更常用 P95/P99，因为均值会掩盖长尾：99 次 100 ms 加 1 次 5 s，均值仍然很好看，但用户会记住那 5 s。

选择口径要看指标用途：

  • 安全阈值：看 worst-case，不能取平均。
  • 用户体验：看 P95/P99，关注尾部。
  • 效率趋势：可以看均值，但要同时报告分布。
  • 回归比较：固定样本量和口径，否则版本之间不可比。

五、实例：SLAM 建图指标

为 SLAM 建图定义一个可执行的指标，可以这样写：

  • 指标：闭环误差（回到起点时的位置偏差）与地图重合度。
  • 采集：同一园区、同一路线、同一速度，重复 20 次。
  • 聚合：闭环误差报告均值、P95 和最大值；地图重合度报告均值。
  • 阈值：闭环误差 P95 ≤ 0.3 m，最大值 ≤ 0.5 m；地图重合度 ≥ 90%。
  • 失败判定：任意一次闭环误差 > 0.5 m 或出现地图断裂，即失败。
  • 环境记录：光照、人流、地面、是否 GPS 拒止。

这样的定义可以被别人复现，也能在版本之间比较。如果只写“建图效果良好”，评审时无法判断，回归时也无法比较。

七、常见误区

  • 没有预言。只看“没报错”“没崩溃”，不判断任务是否完成。
  • 只用均值。掩盖长尾和偶发严重问题。
  • 样本量不足。10 次成功就宣称 98% 成功率。
  • 阈值没有来源。拍脑袋定 95%，既不理解风险也不理解成本。
  • 指标不可复现。没有环境、版本、样本量记录，版本之间不可比。
  • 把统计判定用在安全硬约束上。单次碰撞不能被“成功率 99%”抵消。

八、检查清单

  • 每条测试是否有明确的预言类型？
  • 指标是否定义了公式、单位、采样和聚合方式？
  • 是否选择了单次阈值或 N 次统计，并说明理由？
  • 是否报告了分位数或 worst-case，而不只是均值？
  • 样本量和置信区间是否足够支撑结论？
  • 环境、版本和样本是否记录，能复现和比较？
  • 安全硬约束是否使用零容忍判定？

九、指标口径的计算对比

假设某机器人 20 次任务的端到端延迟如下（单位 ms）：80、82、85、88、90、92、95、96、98、100、102、105、108、110、115、120、125、130、140、500。均值约为 123 ms，看起来还可以；但 P95 约为 140 ms，最大值 500 ms，用户会明显感知到那一次卡顿。

口径结果能说明什么掩盖什么
均值约 123 ms整体平均水平500 ms 的长尾
P95约 140 ms95% 的任务在此以内最坏一次的程度
最大值500 ms最坏情况发生频率
失败次数1 次超阈值是否触发硬约束其他样本的分布

如果指标是“延迟 P95 ≤ 150 ms”，这组数据通过；如果指标是“单次不得超过 300 ms”，这组数据失败。同一个系统，不同口径给出不同结论，所以指标定义必须写清楚。

对于成功率，还要区分“任务成功率”和“单步成功率”。一次任务包含感知、抓取、搬运、放置四步，每步 99% 成功，任务成功率可能只有约 96%。报告时要说明统计的是哪一层，否则数字无法比较。

十、评审与面试追问

  • 问：为什么机器人指标常用 P95/P99？答：因为均值掩盖长尾，而尾部延迟或误差往往直接影响安全、体验和任务完成。
  • 问：什么时候用单次阈值？答：安全硬约束、法规要求和不可接受的单次失效，例如碰撞、越界、急停距离超标。
  • 问：没有参考模型怎么判定？答：用蜕变关系、一致性检查或统计判定，但要说清楚这些预言的局限。
  • 问：指标阈值怎么定？答：来自需求、法规、历史基线、竞品或风险分析；没有来源的阈值只是数字。
  • 问：指标很多怎么选？答：按风险和决策用途选，能回答“是否安全、是否完成任务、是否可接受”即可，不要堆指标。

十一、指标评审问题清单

评审一个指标定义时，用下面五个问题快速判断它是否可执行：

  1. 它回答什么决策问题？如果答不上来，可能不需要这个指标。
  2. 公式和单位是否明确？分子分母是否会被不同人解释成不同意思？
  3. 样本量和统计口径是否写清？单次、N 次、均值还是分位数？
  4. 阈值从哪来？需求、法规、基线还是风险分析？
  5. 数据能否追溯？日志、bag、报告是否存在，谁能复现？

五个问题里有两个答不上来，这个指标就不应该进入准出报告。指标不是越多越好，能支撑决策的少数指标比一堆漂亮数字更有价值。

指标阈值的谈判

阈值很少是纯技术问题，它同时涉及风险、成本和用户体验。测试提出“P95 ≤ 150 ms”，研发可能说硬件达不到，产品可能说用户感知不到差别。合理的谈判方式是拿出三样东西：当前基线、失败后果、改造成本。例如“当前 P95 是 180 ms，超过 200 ms 时用户会明显感到停顿，优化到 150 ms 需要增加缓存，成本约两周”。

如果暂时达不到目标，不要偷偷改阈值。可以设定分阶段目标、增加监控、限制使用场景，或者由风险接受人签字。阈值可以调整，但调整必须有记录和理由。

与其他模块的连接

  • 实验设计与统计把指标口径落成样本量、置信区间和变异控制。
  • Flakiness 与基线用分位数、分布和趋势判断指标波动是否异常。
  • 性能评价复用本课的指标定义模板，补充标准规定的测试条件。
  • 市场准入与认证要求指标、阈值和测试报告能支撑符合性声明。

小结

测试预言回答“怎么判断对”，量化指标回答“好到什么程度”。先选预言类型，再定义指标口径，最后决定用单次阈值还是 N 次统计、用均值还是分位数。一个好的指标应该让别人能复现、能比较、能下钻到原始数据；一个坏的指标只会制造“测试通过”的幻觉。
